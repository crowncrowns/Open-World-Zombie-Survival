# Проверка исправленного Moscow Trees

Дата: 18 октября 2026.

## Источники и причина ошибки

Найдены локальные оригиналы `Moscow_Trees_96_FBX_Unity_Prefabs.zip` и `Moscow_Summer_Trees_Unity_Full.zip`. В первом 96 FBX, во втором 96 GLB (32 дерева × 3 LOD). Исходные архивы не редактировались.

Старые файлы действительно начинаются с `Kaydara FBX Binary  \0\x1a\0` и версии **7400**. Они не являются GLB с заменённым расширением. Поле Creator содержит `OpenAI standalone FBX exporter`.

Двоичный разбор проверил абсолютные смещения завершения узлов и длины блоков свойств. Заголовки узлов соответствуют 32-битной структуре FBX 7400. Старый файл содержит FBXHeaderExtension, GlobalSettings, Definitions, Objects, Connections, Takes; отсутствуют верхнеуровневые FileId, CreationTime, Creator, Documents и References. Наличие сигнатуры и корректно читаемых длин оказалось недостаточным для Unity.

**В Unity 2022.3.36f1 и 6000.6.3f1 воспроизведён отказ `File is corrupted` для всех 96 исходных FBX.** Более терпимый импортёр Blender 4.5.14 открывает пример старого файла.

Чтобы установить причину, выполнены отдельные диагностические эксперименты на копии одного файла Aspen_Dense_LOD0:

| Изменение диагностической копии | Результат Unity |
| --- | --- |
| Пересериализация узлов с теми же свойствами | File is corrupted |
| Только замена footer на footer Blender | File is corrupted |
| Добавление одного FileId / CreationTime / Creator / Documents / References | File is corrupted |
| Добавление **FileId + CreationTime** | Импорт принят |
| Полный комплект служебных узлов Blender | Импорт принят |

Таким образом, на этом файле подтверждена непосредственная причина отказа: **неполная служебная структура, в частности отсутствие пары FileId и CreationTime**. Это наблюдение о проверенных импортёрах, а не утверждение, что любая программа обязана требовать эти поля. Исправленная поставка не использует диагностические патчи: все FBX заново экспортированы штатным экспортёром Blender из исходных GLB.

Есть и отдельная ошибка старого экспортёра для ветра: бинарные имена записаны как `Model::Wind_Trunk\0\1Model`. Blender сохраняет префикс `Model::` в имени объекта, поэтому поиск `StartsWith("Wind_Trunk")` не находит нужные узлы. В проверенном старом примере найдено 0 ожидаемых `Wind_*` узлов. Новый экспорт сохраняет правильные имена и иерархию из GLB.

В `old_import_diagnostics.txt` приведены отобранные строки реальных журналов, включая контрольные варианты. Диагностические FBX не включены в Assets.

## Новый экспорт

- Blender **4.5.14 LTS**, настоящий бинарный FBX 7400.
- 96 GLB импортированы и экспортированы по отдельности штатными операторами Blender.
- Сохранены меши, UV и узлы ветра; оси FBX: -Z Forward / Y Up, единицы из Blender, без запекания клипов.
- Все 96 новых FBX повторно импортированы в чистую сцену Blender.
- Для каждой модели совпали число мешей, вершин, треугольников, мешей с UV и имена узлов Wind. Мировые границы совпали с допуском 0.001 единицы Blender.
- Подробные метрики и SHA-256 каждого исходного GLB и нового FBX — `blender_validation.json`.

## Unity и целевой проект

Целевой проект найден как `E:\git\Open-World-Zombie-Survival`. Прочитаны его ProjectVersion, manifest, GraphicsSettings и QualitySettings. Для теста использована **отдельная копия тестового проекта** с Unity **6000.6.3f1**, URP **17.6.0**, скопированными настройками рендера PC_RPAsset и необходимыми ресурсами из Assets/Settings. Полный игровой проект не запускался вторым редактором и его сцены не изменялись.

Проверено автоматически:

- загрузка всех 96 FBX как модельных ассетов, непустые меши;
- совпадение количества мешей и треугольников с исходниками;
- правильная вертикальная ось и высота каждой модели, допуск 0.01 м;
- наличие Wind_Trunk у всех моделей;
- сборка ровно 32 префабов без ошибок;
- три непустых LOD в каждом LODGroup, CapsuleCollider и MoscowTreeWind;
- ссылки на материалы и текстуры всех Renderer;
- URP/Lit без ошибок компиляции, alpha clip и двусторонняя листва;
- изменение поворота ствола при включённом ветре и возврат в исходную позу при выключении у каждого из 32 префабов.

Всего в 96 моделях **2340 мешей/Renderer**. Проверки пройдены также на 2022.3.36f1 и 6000.6.6f1, но поставка материалов и префабов подготовлена на запрошенной **6000.6.3f1 с URP**.

`unity_validation.txt` содержит итог реального запуска. Рендер и проверки прошли отдельно на Direct3D 11 и Direct3D 12; в последнем запуске ошибок компиляции C# и ошибок шейдеров не было. `Unity_6000.6.3f1_URP.png` — GPU-рендер восьми пород на Direct3D 12, а не концепт-арт. Для диагностического рендера отключена асинхронная компиляция шейдеров: первый кадр сразу после первоначального импорта иначе показывал ещё не готовые варианты шейдера. Это настройка тестового снимка; в пакетный компонент ветра она не добавляется.

## Чего проверка не доказывает

Пакет успешно проходит импорт и указанные функциональные проверки в изолированном проекте. Полная игровая сборка, Play-сценарии Open-World-Zombie-Survival, смена LOD во время движения камеры, производительность массового леса, взаимодействие коллайдеров с игроком и визуальное принятие пользователем не проверены. Деревья сохраняют процедурную стилистику исходников; этот ремонт не заменяет их художественную переработку. HDRP не тестировался.

Ветер — **процедурные повороты Transform в Unity**, не запечённые FBX-клипы, не скелетная деформация и не shader wind. Это прямо отражено в README и исходном LICENSE_AND_NOTES.txt.

## Воспроизводимость

В `Sources` сохранён исходный архив GLB, в `Tools` — действующий скрипт экспорта с повторным импортом. Для повторения Unity-проверки на копии проекта перенесите два C#-файла из Verification в Assets/Editor, expected_metrics.json в корень тестового проекта, импортируйте пакет и запустите `-executeMethod MoscowTreeValidation.Run`. Этот проверочный код требует URP 17.6.0; он намеренно находится вне Assets поставки.

Финальная упаковка дополнительно проверяет количество моделей/префабов, сигнатуры всех FBX, SHA-256 экспортов, целостность ZIP и разрешение GUID-ссылок всех префабов. `.meta` включены в поставку.
