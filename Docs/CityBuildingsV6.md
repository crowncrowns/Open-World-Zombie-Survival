# Городской генератор V6 — передача разработчику и ИИ

25.10.2026. Дополнение к `CityAuthoring.md`. Новые правила включены только в **CityProfileV6**; прежние профили V4/V5 и уже размещённые здания автоматически не переделываются.

## Проверка пользователем

1. Выйти из Play. Открыть **Tools → Zombie Survival → Город — планировка квартала**.
2. В каталоге `Assets/WorldAuthoring/Plans/StarterBuildingCatalog.asset` появился тип **«Городской дом V6 — до 16 этажей, квартиры и водостоки»** (`residential-v6`). Выбрать этот тип у нового участка. Для собственного каталога добавить запись Profile со ссылкой `Assets/ModularBuildings/Generated/CityProfileV6.asset`.
3. Для первого опыта задать 4 этажа / 1 подъезд, свободное место, участок примерно **30×70 м**. Большой запас Z нужен для существующей высокой входной лестницы. Y — уровень пола первого этажа; лишние ступени уходят под Terrain, сам Terrain инструмент не меняет.
4. Нажать «Проверить план», затем «Предпросмотр выбранного дома». Результат показывается в закреплённой строке окна. У четырёхэтажного дома видна скатная крыша; у пятиэтажного — почти плоская, но ещё есть балконы. У 6–16 этажей наружных балконов нет.
5. Только **«Создать выбранный дом (Undo)»** помещает новый дом в сцену. Для другого дома использовать новый участок/ID. Старый дом не заменяется. Для 16 этажей / 6 подъездов начать с участка **110×70 м** в свободном месте; если полный bounds не помещается, увеличить размер по сообщению окна.
6. Квартиры искать внутри `Entrance_N/Floor_N/ApartmentSlot…/ManualContent/Generated apartment`. Их 1–3 на весь дом, только на первых трёх этажах. Входы изначально открыты на 125°. Комнаты содержат `Furnishing anchor` и `Doorway…` для будущего наполнения; закрытые помещения имеют отдельную дверь-заглушку с коллизией.
7. У дома выше 4 этажей найти `CityDetails_V6/Завал — проход с 4 на 5 этаж — подъезд N`. В Inspector компонента **BuildingStairBlocker** назначить **«Префаб завала»**, нажать **«Заменить внешний вид выбранных завалов»**. Можно выделить несколько завалов сразу. Меняется только принадлежащая компоненту модель; коллайдеры самой модели отключаются, отдельный BoxCollider продолжает перекрывать исходящий левый марш. Подъём с третьего этажа по правому маршу остаётся свободным. Использовать готовый prefab из Project с pivot у основания завала. Подгонять модель дочерним Transform, не удалять passageBlocker.

Готовые примеры для отдельной проверки в Prefab Mode: `Assets/ModularBuildings/Generated/CityV6_Review_4F_1E.prefab` и `CityV6_Review_5F_1E.prefab`. Это демонстрационные дома с авторскими ID, а не замена каталогу: новые игровые дома создавать через профиль/новый участок, не тиражировать готовый GeneratedBuilding с прежними ID.

## Правила и принятые решения

- Поддерживается измеренная широкая секция **15×12 м**, высота этажа 3 м; 1–16 этажей, 1–6 подъездов. Год остаётся метаданными, не автоматическим выбором реальной серии Видного.
- Фасад продолжается на полную высоту. Подъездные интерьеры/ApartmentSlot — только до 4 этажа, лестничные переходы — 1→2, 2→3, 3→4. На четвёртом этаже дома выше четырёх этажей ставится физический завал; следующий марш не строится. На верхних этажах закрывается шахта перекрытием.
- Квартиры выбираются среди боковых L/R слотов этажей 1–3. Дублирующий L2 не открывается. На одноэтажном одноподъездном доме доступны два непересекающихся боковых слота, поэтому максимум две квартиры; диапазон по-прежнему 1–3 с ограничением реально доступными слотами.
- В квартире ровно одна кухня, 2–4 жилые комнаты; ванная и туалет выбираются независимо. Кухня и минимум одна жилая комната доступны всегда, остальные случайно. Пока создаются планировки и точки привязки, без мебели/предметов добычи/нового save backend.
- Перегородки крайних квартир обходят реальные торцевые оконные ниши: длины комнат подбираются на сетке 5 см. Полные внутренние дубли переднего/заднего фасада не создаются. На внутренних границах секций квартира получает собственную боковую стену, чтобы нельзя было обойти закрытые комнаты через соседнюю секцию. Проверяются открытость оконных/балконных проёмов и сплошность межсекционной границы.
- `citySeed` в профиле + постоянный `buildingId` задают воспроизводимую планировку через локальный System.Random. Повторный Preview того же участка не меняет квартиры. Для иной планировки использовать копию профиля с другим seed до создания нового дома; не менять ID уже опубликованного дома.
- Балконы — настоящий nested prefab из `Assets/Environment/PostApocalypse/Balconies/Prefabs/Balcony_01_Soviet/`. Перед ними ставится существующий фасадный BalconyExit. Центр балкона в крайних bays 0/4, на 6 м от центра подъезда: между балконным модулем и модулем входа остаётся полный модуль 3 м. На домах 2–5 этажей балконы со второго этажа; у одноэтажного — на первом. Выше 5 этажей наружных балконов нет; лоджии разрешены условием, но эта версия их не добавляет.
- В запросе правила для **5 этажей** пересекались. Принята граница: **1–4 — двускатная крыша, 5–16 — почти плоская 2%**. Уклон скатной крыши `lowRiseRoofPitch`, по умолчанию 18°, диапазон 8–30°. Вентиляция/воздуховоды сохранены и подняты над скатом.
- Водостоки используют готовый ModularRoofKit: желоба, выпуск, offset, прямые секции, нижний слив, хомуты, анкеры и кронштейны. Четыре вертикальные трассы у углов длинных фасадов. Соединения стыкуются по RoofSnapPoint, последняя короткая секция корректируется только по Y. Нижний выпуск расположен у первого этажа и направлен от стены. Крепления повторяются по высоте.

## Код и ограничения для следующего разработчика

`BuildingGenerator.CreateProfile()` теперь возвращает V6. Старый factory доступен как `CreateV5Profile()`, исходные assets не мигрировать. `extendedCityRules` по умолчанию false, поэтому старые сериализованные профили сохраняют прежнюю ветку 1–9 этажей / 1–8 подъездов.

Новые детали — `Editor/BuildingCityDetails.cs`; квартиры — `Editor/BuildingApartments.cs`; метаданные — `GeneratedApartment`, `GeneratedApartmentRoom`; блокировка — `BuildingStairBlocker` + UI Toolkit Editor. Все находятся в `Assets/ModularBuildings`. Геометрия новых домов создаётся штатным генератором, не второй независимой системой. Производные mesh assets в `Generated/CityRoofMeshes` и прежних immutable caches сохранять вместе с .meta. Не переписывать исходные vendor-prefab/меши.

Для открытых квартир `DoorInteractable.SetInitialOpenPose` сохраняет закрытую опорную rotation и начальный открытый угол. Просто повернуть hinge в Editor недостаточно: Awake иначе принял бы его за закрытую позу. Старые двери без authored-флага работают прежним образом. RestoreWorldState остаётся главным при загрузке сохранения; второй формат сохранения дверей не создавать. Новые авторские метки квартир не являются SaveIdentity.

В V6 **не запускается прежний глобальный SeamUnion/CoplanarAudit**: его проход по всему высотному дому слишком дорог, а старые проверки требуют лестницы/пустые интерьеры на всех этажах. V4/V5 сохраняют этот путь. Для V6 используется отдельная проверка количества этажей/лестниц/завалов/балконов/вентиляции, квартир, проходимости через унаследованные коллайдеры, общие проверки ID/material/mesh/missing script. Полную прежнюю сертификацию швов и capsule-проход всего здания этому результату не приписывать. Дальше нужны отдельный локальный seam-проход и оптимизация стоимости домов, а не возврат квадратичного общего прохода.

`CityBlockBuilder` выполняет production Validate нового V6 до публикации и полный bounds-контроль участка. Не добавлять скрытый Rebuild/overwrite существующих домов. Не сохранять рабочую сцену автоматически. Предпросмотр может создавать только новые immutable производные meshes; проверка плана остаётся read-only.

Не путать `CityBlockBuilder.Validate` (проверка данных плана, без Physics) с `BuildingGenerator.Validate` (проверка уже построенной геометрии). Последняя перед V6 collider-пробами вызывает Physics.SyncTransforms: после свежего поворота/переноса дома PhysX иначе проверяет прежние позы. Сам `ValidateInheritedPaths` не синхронизирует/не авторит сцену.

## Фактически проведённые проверки

Unity 6000.6.3f1, текущий Editor, изолированные Preview Scenes. Общие итоговые отчёты и кадры: `Verification/CityBuildingsV6` (исходные локальные материалы остаются в `work/CityV6_20261025`).

- 4 этажа / 1 подъезд: скатная крыша, балконы с разрывом от входа, квартиры и водостоки; кадр `F4_E1.png` осмотрен.
- 5 этажей / 1 подъезд: почти плоская крыша, балконы, завал 4→5; кадр `F5_E1.png` осмотрен.
- 16 этажей / 6 подъездов: 18 лестничных модулей, 6 завалов, интерьеров выше четвёртого нет, внешних балконов нет. Production validator прошёл. Около 18,4 тыс. Renderer: это проверка геометрии, а не разрешение тиражировать такие дома по всему городу без оптимизации. Кадр `F16_E6.png` осмотрен; наружные входные лестницы в Preview не заглублены в Terrain.
- Стыки Pipe в четырёх трассах совпали с точностью 1 мм и встречными направлениями; нижние выходы направлены наружу, Y около 0,51 м.
- Seed 1–6: встречались 1, 2 и 3 квартиры, разные жилые/мокрые/доступные комнаты; повтор seed/ID дал тот же результат, UnityEngine.Random.state не изменился.
- После исправления окон/границ повторены все шесть seed, сохранение дверей и случаи 4F1E / 5F1E / 16F6E: PASS. Дополнительно полный плановый PreviewLot 5F2E, yaw 37°, мировая позиция (5000,0,5000), bounds и повторная геометрическая валидация: PASS. Проверка входящего марша 3→4 на 31 позиции на каждый завал: PASS. Осмотрены `Plan5F2E.png` и диагностический `ApartmentCutaway.png` (верхние этажи скрывались только во временной сцене).
- Нижняя граница 1F1E: PASS (балконы/скат/одна квартира, лестничных переходов и завалов нет). Финальное состояние компилятора: compilationFailed=false, compiling=false, текущих Console Errors=0; 18 прежних предупреждений не исправлялись этой задачей.
- Сохранение нового prefab → LoadPrefabContents → инициализация двери: все двери открыты на 125°, ссылки и планировка сохранены.
- Замена модели завала сохранила отдельную коллизию прохода. Примеры сохранены только как новые prefab assets.
- Исходный профиль и файлы ранее открытых сцен сохранили SHA во время variant-проверки; рабочие сцены намеренно не перестраивались/не сохранялись.

Проверки проходов — геометрические зонды против собственных коллайдеров дома, не полноценное движение игрока/NavMesh. Main Play, standalone, массовый FPS, все варианты мебели, сохранение добычи и все комбинации зданий не проверены. Служебный Pipeline timeout 5000ms возможен у долгой команды; окончательный результат смотреть в отчёте, не перезапускать сборку вслепую. Прежний TerrainRoadSurfaceMap может запускать свой отложенный OnEnable Rebuild после domain reload и помечать сцену dirty; эта автоматизация не изменялась.
