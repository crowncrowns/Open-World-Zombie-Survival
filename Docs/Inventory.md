# Этап 8: предметы и перенос добычи

Открой `Assets/CharacterTesting/CharacterTest.unity`. Предметы лежат около `(8…12, 0, -20)`, ящик — `(13, 0, -17)`. E подбирает стопку или открывает ящик; Tab открывает рюкзак; Tab/Escape закрывают окно. Выбери слот мышью, затем «В ящик», «В рюкзак», «Перенести 1», «Выбросить всё» или «Выбросить 1». Для подбора смотри прямо на маленький предмет, как при обычном взаимодействии.

В рюкзаке 12 слотов. Консервы складываются по 5, ткань — по 10. Оружие реализовано этапом10, состояние прочности — Т2. Употребление, эффекты экипировки, крафт, масса и сохранение на диск остаются отдельными этапами. Окно показывает категорию/подкатегорию, прочность экземпляра и магазин оружия. Это рабочий прототип на IMGUI; для окончательного оформления можно заменить только представление, сохранив ItemStorage и API переноса. Выбор слотов рассчитан на мышь; полноценная навигация геймпадом ещё не реализована.

Мир не останавливается при открытом рюкзаке: зомби может напасть. Движение, обзор и E блокируются. Смерть закрывает окно, предметы остаются в рюкзаке после возрождения. Удаление/выключение ящика, отход дальше Container Distance или потеря фокуса закрывают окно. Поза игрока сохраняется.

## Контракты для разработчика и ИИ

Т4: PlayerInventory блокирует управление от собственного владельца через `FirstPersonController.SetGameplayInputLock(this, true/false)`. Close/OnDisable снимают только свою блокировку, не сохраняют и не восстанавливают общий bool. Открытие проверяет итоговый `AcceptingGameplayInput`, поэтому рюкзак не открывается поверх дерева навыков или сервисного окна. Внешний запрет ввода и чужие блокировки переживают закрытие рюкзака. После закрытия удерживаемые кнопки действий необходимо отпустить; WASD не задерживает возврат управления. Подробнее — [ServiceSessions.md](ServiceSessions.md).

- `ItemDefinition` — общий ScriptableObject типа: стабильный ID, название, описание, лимит стопки и префаб в мире. Меню создания: **Create → Zombie Survival → Предмет**. Не хранить в нём количество, владельца и состояние конкретного экземпляра.
- `ItemStack` — конкретная стопка: ссылка на тип, количество и уникальный ID. При разделении создаётся новая стопка с новым ID; при объединении остаётся ID принимающей стопки. На Т2 индивидуальная прочность реализована для оружия/снаряжения, которые занимают отдельные слоты; модификаторы пока отсутствуют. Copy — только снимок для чтения, не команда переноса.
- `ItemStorage` — общая модель слотов игрока, ящика и будущих NPC. `GetSlot` только читает. `TryAddAll` принимает всё количество либо ничего; `TransferTo` переносит максимально возможное количество, оставляя остаток в источнике. Два хранилища обновляются до события `Changed`. Не править список слотов извне и не дублировать правила вместимости в UI.
- `WorldItem : Interactable` — подбор через существующий луч E, дистанцию и препятствия. Если вся стопка не помещается, объект остаётся на земле. Флаг collecting защищает от повторного подбора в том же кадре.
- `StorageContainer : Interactable` открывает `PlayerInventory` и использует такой же ItemStorage. Ящик не знает ничего о движении, камере или модели игрока.
- `PlayerInventory` управляет окном, блокировкой ввода, дальностью до ящика и безопасным выбрасыванием. Перед списанием проверяются префаб с WorldItem, препятствия и земля. При отказе предмет остаётся в исходном слоте. Префаб мирового предмета держать примерно в пределах радиуса 0,18 м либо расширить проверку по его Collider bounds.

Количество слотов уменьшением параметра не удаляется: уже созданные слоты сохраняются, чтобы не потерять предметы. Настраивать вместимость перед первым запуском; для реального уменьшения заполненного контейнера позже понадобится явное правило обработки излишков.

Исходные типы и префабы находятся в `Assets/CharacterTesting/Items`. Чтобы добавить тип: создай ItemDefinition, визуальный префаб с Collider + WorldItem (Rigidbody необязателен), свяжи их, у размещённого WorldItem назначь тип и количество. Соблюдай уникальность Item ID самостоятельно до появления базы предметов/сохранений.

## Проверка

1. Подобрать консервы и ткань, посмотреть их количества в Tab.
2. Положить часть и всю стопку в ящик; забрать обратно. Суммарное количество не меняется.
3. Заполнить рюкзак: повторный подбор не удаляет объект из мира. Полный ящик отказывает без потери предмета; частично свободный принимает только то, что помещается.
4. Выбросить один предмет и всю стопку; подобрать обратно. Попытка выбросить в стену не списывает предметы.
5. Открыть окно, нажать W/E/мышь: персонаж не двигается и не взаимодействует с миром. Закрыть и проверить возврат управления.
6. Умереть с открытым окном, возродиться; содержимое рюкзака сохраняется в рамках текущей игровой сессии. Сохранение после перезапуска игры относится к этапу 11.

Инструмент повторной настройки полигона: **Tools → Character Lab → Set Up Inventory and Crawl Pursuit**. Он добавляет недостающие объекты и перепекает обе поверхности; не предназначен для сброса содержимого во время Play.


## Оружие (этап 10)

Оружие не складывается в стопки. Его ItemStack содержит магазин и сохраняет ID/боезапас при переносе и выбрасывании. Для перемещения экземпляров не использовать TryAddAll: передавайте состояние через TransferTo/TryAddStack/WorldItem.Initialize(ItemStack). В рюкзаке доступна кнопка «Экипировать». Подробности: [Weapons.md](Weapons.md).

## Т2 — рабочий контракт (реализация)
ItemDefinition.Category/Subcategory имеют стабильные enum ID; Weapon/Equipment — индивидуальные вещи с MaxStack 1 и MaximumDurability типа. ItemStack хранит Durability и stateVersion: старое состояние версии 0 становится полным, явный 0 версии 1 остаётся сломанным. Магазин независим от прочности. GetSlot остаётся живой read-only ссылкой (важно PlayerWeapons). Copy(amount) теперь non-transferable read-only snapshot: не передавать его в TryAddStack/WorldItem.Initialize. Новый экземпляр — constructor с новым ID; фактическое владение передавать TransferTo или TryExtract(out original), затем TryAddStack/WorldItem.Initialize(original). Mutations только через ItemStorage, включая TrySetDurability. Snapshot/repeated import/совпадающий ID отклоняются. Legacy batch распадается без потери количества, при необходимости расширяя slots: исходный ID/магазин только первому, новым экземплярам новые ID/пустой магазин. Для ресурсов split новый ID, merge ID получателя, полный перенос в пустой слот сохраняет ID. Drop создаёт неактивный world object, извлекает оригинал и при сбое Initialize возвращает его через rollback.


Категории и подкатегории — enum с явно фиксированными числовыми ID и русскими InspectorName, а не строки из displayName. Боеприпасы/продукты/медицинские средства — общие подкатегории, конкретный калибр задаётся ссылкой Ammo на ItemDefinition. Новые enum значения добавлять с новым ID, старые не перенумеровывать. Неизвестный старый тип остаётся Uncategorized с однократным предупреждением. Окно рюкзака показывает категорию/подкатегорию и текущую/максимальную прочность.


## Этап 11 персонажа — потребление и общий снимок

Реализован [хотбар CM-01–CM-03](Hotbar.md): по умолчанию 5 слотов, 1–5/колесо, Q выбросить одну единицу, действия мышью. Назначение — кнопками в собственном рюкзаке. Ссылки только по InstanceId собственного ItemStorage, без копий/второго хранилища; уход экземпляра очищает назначение, split/merge не перепривязываются по типу. Общая проверка места и перенос оригинала выделены в WorldItemDropService; PlayerInventory и хотбар используют один сервис.

Еда/напитки подключаются через отдельный ConsumableDefinition в PlayerNeeds, не меняя ItemDefinition категорий/торговли. «Употребить 1» в рюкзаке расходует обычный ресурс при полезном эффекте. Сохранение F5/F9 включает все хранилища и мировые предметы сцены, сохраняет ID/прочность/магазин. Внутренние RestoreSaved/ReplaceSavedSlots/NotifySavedRestore/RetireForRestore предназначены только загрузчику; обычный перенос сохраняет прежний контракт. Границы Wallet и планы адаптеров — [CharacterSurvivalAndSaving.md](CharacterSurvivalAndSaving.md).
