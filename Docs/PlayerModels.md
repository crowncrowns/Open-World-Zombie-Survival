# Модель игрока и её замена

## Что подключено

На корень `Assets/CharacterTesting/Prefabs/CharacterTestPlayer.prefab` добавлен `PlayerVisual`. Его `Model Prefab` ссылается на `Assets/Characters/Asuna/AsunaPlayerModel.prefab`. В сцене CharacterTest используется этот префаб игрока. Общая SampleScene на данном этапе не менялась.

Модель живёт в дочернем `VisualRoot`. `FirstPersonController`, CharacterController и камера остаются на прежних местах. Смена внешности не меняет размеры капсулы, скорости, управление или положение камеры. Камера не привязана к анимированной голове, поэтому движения анимаций не трясут обзор.

Asuna использует Humanoid Avatar из скачанного набора. Подключены idle, ходьба и бег во всех восьми направлениях, приседание на месте и движение в приседе. Движение выполняет CharacterController, Root Motion выключен. Оружие и кобуры из демонстрационного префаба отключены; это подключение внешности, а не реализация оружия.

Материалы используют URP. Оригинальные FBX, материалы, анимации и демонстрационные префабы в FreeTestCharacterAsuna не редактировались. Наши настройки находятся в отдельном префабе, контроллере анимаций и производных Mesh assets.

## Быстрая замена готовой внешности

1. Останови Play.
2. Открой `CharacterTestPlayer.prefab` в Prefab Mode и выбери корневой объект.
3. В компоненте **Player Visual** перетащи новый префаб внешности в **Model Prefab**.
4. Нажми **Apply / Replace Model**. Заменяется только управляемая модель в VisualRoot.
5. При необходимости настрой **Local Position**, **Local Euler Angles**, **Local Scale**, снова нажми кнопку и сохрани префаб.
6. Запусти CharacterTest. Проверь ноги на земле, вид от первого лица, бег и приседание в тоннеле.

При редактировании компонента на экземпляре игрока в сцене изменения станут overrides именно этой сцены. Для изменения всех экземпляров работай в Prefab Mode. Кнопка замены поддерживает Undo. Изменения в Play временные.

## Как подготовить ещё одну модель

1. Создай пустой объект и помести модель дочерним объектом. Корень этой обёртки должен иметь масштаб 1 и находиться у стоп; саму модель можно масштабировать и поворачивать внутри. Сохрани обёртку как отдельный prefab вне папки поставщика.
2. Не добавляй в обёртку контроллер игрока, ввод или дополнительную игровую камеру. Это префаб только внешности. По умолчанию PlayerVisual отключает вложенные коллайдеры, физику, камеры и AudioListener; компоненты собственной игровой логики в него помещать не следует.
3. Добавь на обёртку **PlayerModelDefinition**. Укажи её Animator и список **First Person Hidden Renderers** — отдельные меши головы, волос, глаз и других деталей, способных перекрывать камеру. Если нужна отдельная геометрия для первого лица, назначь её в **First Person Only Renderers**. Их можно изначально отключить в префабе: PlayerVisual включает их, автоматически скрывает вне собственной камеры и обновляет skinning вне кадра.
4. Для повторного использования наших анимаций настрой в импорте модели **Rig → Humanoid**, проверь Avatar и назначь её Animator контроллер `Assets/Characters/Animation/PlayerLocomotion.controller`. Работоспособность переноса анимаций зависит от корректного Humanoid Avatar конкретной модели.
5. Для собственной схемы анимаций можно назначить другой Animator Controller и настроить имена параметров в PlayerVisual. Несуществующие параметры пропускаются. Модель без Animator также допускается: она будет отображаться без анимации.

Нельзя использовать целый CharacterTestPlayer в поле Model Prefab: это создало бы второго игрока внутри первого; компонент отклоняет такие префабы.

## Вид от первого лица

У PlayerVisual есть три режима **First Person Visibility**:

- **Hide Selected Renderers** — детали из списка PlayerModelDefinition скрыты только при рендере собственной камеры игрока, но отбрасывают тени. При этом показываются First Person Only Renderers, если они настроены.
- **Shadows Only** — вся модель скрыта от собственной камеры и остаётся в тенях. Подходит для моделей с единым мешем головы и тела, пока не подготовлена отдельная геометрия.
- **Show Whole Model** — полная модель, включая голову. Удобно для диагностики, но она может перекрывать камеру.

В Scene View и других камерах модель видна целиком. Отключение видимости головы не удаляет кости и не ломает Humanoid-риг.

У Asuna голова объединена с телом в BodyMesh. Созданы отдельные производные меши тела и головы по исходным submeshes и дополнительный вариант нижней части тела для собственной камеры. Они используют прежние кости, веса и материалы. Для собственной камеры скрыты полный меш тела, голова, волосы, глаза и верхняя броня: это предотвращает попадание камеры внутрь груди и наплечников. Показываются ноги и нижняя броня. В других камерах видна полная модель; её тени сохраняются. Оригинальный FBX сохранён. Производные mesh assets сохранены в бинарном формате и отмечены для Git LFS.

Для другой объединённой модели недостаточно скрыть кость Head: skinned mesh от этого не исчезнет. Используй Shadows Only или подготовь отдельную геометрию головы.

## Настройки анимации

`Walk Animation Speed`, `Run Animation Speed`, `Crouch Animation Speed` — физические скорости, соответствующие анимациям; начальные значения 4 / 7 / 2 м/с. Если изменишь скорости передвижения, проверь и эти значения, чтобы момент перехода между ходьбой и бегом соответствовал движению.

`Animation Playback Speed` — общий темп воспроизведения. `Animation Damping` — сглаживание параметров. Смещение и масштаб модели не компенсируют неверные размеры CharacterController — настрой капсулу отдельно до запуска Play.

Параметры нашего Animator Controller:

| Параметр | Тип | Значение |
| --- | --- | --- |
| MoveX | Float | Боковое движение: ±1 ходьба/присед, ±2 бег |
| MoveZ | Float | Продольное движение: ±1 ходьба/присед, ±2 бег |
| Speed | Float | Фактическая горизонтальная скорость в м/с |
| Crouched | Bool | Персонаж находится ниже исходной высоты |
| Prone | Bool | Отдельное состояние ползания, приоритетнее Crouched |
| Dead | Bool | Смерть с приоритетом над движением, паркуром и ползанием |
| Grounded | Bool | Контакт CharacterController с землёй |
| VerticalSpeed | Float | Вертикальная скорость прыжка/падения |
| ParkourState | Int | 0 — обычное движение, 1 — вис, 2 — подтягивание, 3 — преодоление, 4 — перекат |

Параметры движения рассчитаны по фактической скорости капсулы, поэтому упор в стену не должен оставлять полноценный бег на месте. Диагональные значения нормализованы по длине вектора.

На этапе 4 подключены анимации прыжка, падения, приземления и Humanoid IK рук при висе. Специальные клипы подтягивания, преодоления и переката пока заменены временными позами; физическая механика описана в [Parkour.md](Parkour.md). На этапе 5 добавлено процедурное ползание через PlayerCrawlAnimation и Humanoid IK; оно сохраняется при замене Humanoid-модели. Настройки находятся на корне игрока. Для собственного контроллера нужен Bool Prone и IK Pass базового слоя. Анимации боя и экипировки, а также поиск земли для IK стоп пока не подключены. Исходное скрытное приседание Asuna выше физической капсулы 1 м: для полного внешнего вида в низких тоннелях потребуется более глубокая анимация или дополнительная настройка позы.

На этапе 7 состояние Dead использует HumanF@Death01 из Kevin Iglesias Human Animations. Root Motion остаётся выключенным. При собственной замене Animator Controller добавь Bool Dead и переход в нужный клип смерти, а при сбросе Dead — возврат к движению. Контроллер и здоровье не зависят от наличия клипа.

## Замена из кода

```csharp
playerVisual.SetModel(otherAppearancePrefab);
```

Метод удаляет прежнее управляемое представление и подключает новое, сохраняя игрока. `SetModel(null)` убирает внешность. `ModelInstance` и `ModelAnimator` доступны для чтения.
