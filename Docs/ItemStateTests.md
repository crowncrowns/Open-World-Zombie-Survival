Перед изготовлением визуала выполнен Unity Search по bag/backpack/pack: подходящих моделей не найдено. Использован явный прототип вне vendor, без заявления о готовой модели рюкзака.

Существующий ящик принимает и возвращает экземпляры. TestBackpack не добавляет вместимость и не реализует экипировку. Новые материалы не создавались, cloth остаётся существующей тканью.

Ассеты: `Assets/CharacterTesting/Items/T2/TestBackpack.asset`, `.prefab`, `.mat`. Настройки типа доступны в существующем окне **Tools → Zombie Survival → Настройки персонажа и зомби → Инвентарь → Тип предмета**. Это редактор самого ItemDefinition, без второго источника параметров.

## Контракт и ручная проверка

- Создание нового экземпляра: `new ItemStack(type, 1, initialDurability)`, новый ID. Без явного состояния прочность полная.
- `GetSlot` возвращает живую ссылку с публичными свойствами только для чтения; PlayerWeapons сохраняет эту ссылку.
- `Copy(amount)` — non-transferable read-only snapshot. Его нельзя вставлять через TryAddStack или WorldItem.Initialize. Все прежние runtime caller'ы Copy для переноса удалены.
- Фактический перенос: `TransferTo` либо `TryExtract(out original)` и затем `TryAddStack(original)` / `WorldItem.Initialize(original)`. Повторный импорт owned оригинала или совпадающего ID отклоняется. Нет глобального registry владения.
- `TrySetDurability(index, value)` меняет состояние через ItemStorage; NaN/Infinity отклоняются. Ноль версии 1 остаётся нулём, версия 0 без данных мигрирует в полную прочность.
- Ресурсы: полный перенос в пустой слот сохраняет ID; split создаёт новый ID отделённой части; merge оставляет ID получателя. Общий расход количества не меняется.
- Legacy пачки оружия/снаряжения разделяются без потери количества; при необходимости список slots расширяется. Первый сохраняет прежний ID/магазин, остальные получают новые ID и пустые магазины. Одно старое значение прочности применяется к каждому представленному экземпляру.
- Drop создаёт неактивный объект мира, извлекает оригинал и только после успешного Initialize включает объект. При исключении инициализации возвращает извлечённое состояние rollback-операцией без потери вещи.

Ручной сценарий: подобрать оба рюкзака; увидеть 35/100 и 80/100; перенести в ящик и обратно; выбросить и подобрать; проверить то же состояние. Для пистолета зарядить магазин, выстрелить, перенести/выбросить/подобрать и проверить остаток. Заполнить ящик, проверить полный отказ и частичный перенос ресурсов без изменения суммарного количества.

## Подтверждённые проверки

**Tools → Character Lab → Check T2 Inventory Contracts** (`InventoryT2Checks.Run`): 17 содержательных проверок прошли через live Editor. Покрыты разные экземпляры 35/80, ID и оригинальные ссылки; запрет owned/snapshot duplicate; атомарные события переноса; возврат из ящика; NaN/Infinity; Unity JSON с явным нулём; legacy без полей прочности; пачка из трёх пистолетов с суммой магазинов 7; настоящий prefab save/load; частичная вместимость с общим количеством еды 13; полный отказ; split/merge ткани с итогом 9; reload 12 и расход одного патрона (11 в магазине + 8 в запасе); extract/world/import с сохранением ID, прочности 47 и магазина 11; лимиты 60/5/10/1. Временные объекты и probe очищаются в finally; занятый путь probe не перезаписывается.

В Play на CharacterTest использованы реальные адаптеры существующей системы: WorldItem.Interact подобрал оба рюкзака; PlayerInventory.Drop и последующий подбор сохранили ID и прочность 80. Перенос в настоящий сценовый StorageContainer и обратно сохранил ID/состояние/количество. Настоящий пистолет был экипирован PlayerWeapons; Storage.Reload и SpendRound оставили ту же живую Equipped-ссылку. После Drop/pickup сохранены тот же ID, прочность 47 и loadedRounds 11. Это проверки gameplay API, а не имитация нажатий клавиатуры; ввод не менялся.

Координатор просмотрел настоящий GameView через Computer Use: категории по-русски, рюкзаки 80/100 и 35/100, пистолет 47/100 с магазином 11 и патроны 8/60 читаются. Отдельного PNG окна нет: CLI camera-render не захватывает IMGUI; `Temp/T2-inventory-state.png` не является доказательством UI.

После проверки Play закрыт, исходные reload options восстановлены. EditorSettings diff пуст; compileFailed=false; сцена сохранена и clean. Наши временные Search окна закрыты.

## Ограничения

Нет игровых сохранений на диск, торговли, Wallet, ремонта, боевого износа и эффектов экипировки. Сериализация проверена Unity JSON и временным prefab save/load, что не является системой сохранения игры. Тестовые изменения инвентаря относятся только к Play и отброшены обычной перезагрузкой сцены. Типы должны иметь уникальные Item IDs; разные ItemDefinition не объединяются даже при ошибочно одинаковом строковом ID.
