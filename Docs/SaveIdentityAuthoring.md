# Уникальные ID при расстановке NPC

Обновлено 19.10.2026. В Edit Mode зомби можно расставлять обычным Ctrl+D, копированием/вставкой или перетаскиванием готового prefab. `Assets/Editor/SaveIdentityAuthoring.cs` назначает новым сценовым компонентам SaveIdentity значения `scene-<GUID>`. ID оригиналов и существующих объектов сохраняются. Механизм общий для сохраняемых NPC/объектов, без проверки имени или типа зомби.

## Контракты для второго разработчика и ИИ

- SaveIdentity остаётся пассивным runtime-компонентом: не генерировать ID в Awake/OnValidate/OnEnable. Play, загрузка сохранения, переимпорт, открытие сцены и перезагрузка скриптов не должны менять ID существующих объектов. Снимок известных компонентов захватывается при загрузке редакторного сервиса, открытии/закрытии сцены, Undo/Redo и возвращении из Play.
- Новые компоненты определяются относительно этого снимка; обрабатываются также неактивные копии и дочерние SaveIdentity, включая хранилища. Обработка отложена до editor delayCall, а sceneSaving выполняет её перед сериализацией. Повторный проход ничего не меняет.
- Уже имеющийся WorldSaveObject новой копии добавляется один раз в конец `sceneObjects` единственного WorldSaveRegistry той же сцены. Компоненты WorldSaveObject/адаптеры не добавляются автоматически: правильный prefab должен уже содержать нужные адаптеры. Вложенные корни и отсутствие/несколько реестров сообщаются предупреждением; исправить конфигурацию, затем выполнить явную команду ремонта.
- Prefab assets, Prefab Stage, preview scenes и DontSave-объекты исключены. Не применять сценовый ID обратно к prefab. `player` зарезервирован; копия игрока и её дочерние IDs/корни не переназначаются и не регистрируются автоматически.
- ID и регистрация записываются через Undo и prefab property modifications. Для обычного Duplicate один Undo удаляет копию и её запись, Redo возвращает тот же новый ID. На Undo/Redo сервис захватывает снимок, не генерирует новые значения.
- Runtime-создание сохраняемого NPC по-прежнему только `WorldSaveRegistry.Spawn(WorldPrefabDefinition, position, rotation)`: корень получает `runtime-<GUID>`, дочерние IDs привязаны к нему. Не заменять это обычным Instantiate и не вызывать редакторный сервис из игровых сборок.
- Setup-инструменты, намеренно задающие конкретные ID новым объектам, должны закончить построение и вызвать `SaveIdentityAuthoring.CaptureBaseline()` перед сохранением. Это явное принятие уже проверенных ID; не вызывать посреди обычного копирования, иначе оно попадёт в исходный снимок без обработки.

## Старые конфликты

При открытии старой сцены автомат не угадывает оригинал. Меню **Tools → Zombie Survival → Save IDs → Отчёт без изменений** показывает план. **Исправить ID и регистрацию активной сцены** применяет ремонт; сцену затем нужно сохранить.

`Repair(scene, dryRun, preferredOriginals)` сохраняет явно указанный оригинал. Без указания можно выбрать только единственного участника конфликтной группы, принадлежащего уже зарегистрированному WorldSaveObject. Если зарегистрированных претендентов несколько либо нет, команда отказывает: имя и порядок иерархии/реестра доказательством не считаются. Пустым ID назначаются новые значения. Неоднозначные originals, конфликт игрока или ошибка регистрации проверяются до применения; при ошибке ремонт не меняет IDs. Dry-run генерирует пример будущих IDs; отдельный apply может выдать другие значения.

## Ремонт CharacterTest

Оригинал ZombieMaleActor (prefab instance 82329964) сохранил ID `59f0f3b2f82c40dca91c91486531b71f`. Изменены только две копии:

| Объект | Новый ID |
|---|---|
| ZombieMaleActor (1), instance 291368290 | `scene-79d199592467472190c3d3b2e53e8ad3` |
| ZombieMaleActor (2), instance 1281865629 | `scene-5ccd94c9d9b04e4a8572faf0a2b965c7` |

Все 23 сценовых SaveIdentity уникальны; остальные 21 ID неизменны. Оба существующих WorldSaveObject добавлены в реестр: 12 → 14 корней. Сохранена только CharacterTest; несохранённые изменения Assets/1.unity оставлены в редакторе. В сравнении с резервной копией изменены два overrides persistentId и список реестра; добавлены две stripped-ссылки Unity на уже существующие WorldSaveObject, новые NPC не создавались. Резервные копии/карта ID/отчёт: `S:/Games/Unity Projects/_CodexRecovery/SaveIdentity-20261019`.

Добавление авторских корней меняет состав области. Старый save с другим набором корней не мигрируется автоматически; нужен новый снимок либо отдельная миграция. Проверки полноты адаптеров, геометрии и других областей сохраняются: устранение коллизий не означает завершение Т13 или аудит всего мира.

## Проверки

- `Tools → Zombie Survival → Проверить ID сценовых копий` / `SaveIdentityAuthoringChecks.Run()`: 14 проверок в отдельной временной additive сцене; она сохраняется в Temp для проверки sceneSaving и удаляется. Пользовательские сцены не сохраняются. Проверяются original/child IDs, повторный проход, регистрация, сохранение исторических коллизий до явного ремонта, dry-run, отказ при неоднозначности, explicit preferred originals, исключение дерева игрока и новый пустой ID.
- В отдельном Unity 6000.6.3f1 выполнен настоящий `Unsupported.DuplicateGameObjectsUsingPasteboard()`, затем отдельные Undo/Redo между кадрами: исходные root/child IDs сохранились, копии получили новые, реестр 1 → 2 → 1 → 2, Redo сохранил оба новых значения.
- Запись и повторное открытие тестовой сцены сохранили IDs и clean-флаг; перетаскивание prefab назначило IDs экземпляру, template остался прежним. В Prefab Stage отдельный проход сохранил ID шаблона и clean-флаг.
- В Play два `WorldSaveRegistry.Spawn` получили разные runtime-IDs; после нескольких кадров значения прежние, original ID и все остальные уникальны. После Stop сценовые IDs прежние, runtime-объектов в Edit нет; после повторной компиляции карта всех 23 ID пользовательской сцены совпала с сохранённой.
- Ручная проверка: Ctrl+D зомби в Edit, проверить отличный ID и запись реестра; Undo/Redo; сохранить и открыть сцену; Play/Stop — IDs прежние. Runtime-зомби создавать через CM04-консоль.
