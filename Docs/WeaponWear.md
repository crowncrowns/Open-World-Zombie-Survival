# Т8 — реальный износ оружия

19.10.2026. Пользователь согласовал объём: **только оружие**, слоты брони и её защита/износ — позже. Ремонт остаётся этапом Т9, меню верстака — Т10. Существующие категории снаряжения не означают реализованную экипировку брони.

## Настройка и поведение

В WeaponDefinition есть **«Износ за применение»** (`durabilityCostPerUse`), единицы прочности за подтверждённое действие. В существующих ассетах `Assets/Weapons/Definitions/ArmyPistol.asset` задано **0,5** за выстрел, `CampingAxe.asset` — **1** за завершённый удар. Это стартовые коэффициенты, их можно менять в Inspector. Максимум остаётся в ItemDefinition, текущее значение — в живом ItemStack. Настройки движения, HP и слоты рюкзака не менялись.

- Огнестрел: расход на успешное списание патрона и начало выстрела, включая промах или попадание в преграду. Патрон и прочность меняются вместе до одного Changed. Пустой магазин, cooldown, закрытое управление, сломанный предмет и неверная настройка ничего не расходуют.
- Ближний бой: расход в момент завершения разрешённого windup, включая промах. Старт замаха сам прочность не списывает. Отмена до этого момента при убирании/смене оружия, открытии меню, потере управления или смерти не изнашивает предмет. Выносливость по прежнему правилу расходуется за начатый замах и при отмене не возвращается.
- Последний допустимый удар/выстрел наносит полный обычный урон, даже если его стоимость больше остатка прочности. Остаток ограничивается нулём. Следующая атака отказывает с сообщением «Оружие сломано».
- Ноль не удаляет вещь, ID, магазин или назначение хотбара. Перенос, продажа, reload, ходьба и открытие меню не расходуют прочность. Reload сломанного оружия сам по себе не чинит его и не разрешает атаку.
- Значение расхода 0 явно отключает дальнейший износ исправной вещи, но не разрешает атаку уже сломанной. Отрицательные/NaN/Infinity значения отклоняются до расхода патронов и выносливости; редакторский WeaponValidation также сообщает ошибку.

Текущая прочность/«СЛОМАНО» показаны в существующем HUD оружия. Рюкзак и окно торговли используют прежнее отображение состояния и цены. Открытие UI не добавляет отдельного состояния предмета.

## Контракт для второго разработчика и ИИ

Точки входа: `Assets/Scripts/Weapons/PlayerWeapons.cs`, `WeaponDefinition.cs`, `Assets/Scripts/Inventory/ItemStorage.cs`, `Assets/Scripts/Persistence/PlayerSaveSystem.cs`.

- `ItemStorage.IsWeaponBroken(item)` — единая проверка нуля для оружия. `CanUseWeapon(original, wear, spendRound, out reason)` — предварительная проверка; `TryUseWeapon(...)` повторно проверяет владение живым оригиналом и атомарно меняет патрон/прочность. Copy-снимок или вещь другого владельца не принимается. `spendRound=false` используется для завершённого melee; огнестрел проходит с true. Для нового вооружённого NPC вызывать этот API только после его собственных проверок атаки, а не добавлять PlayerWeapons на NPC.
- При Т8 PlayerWeapons больше не использует отдельный SpendRound для выстрела. Не вызывать дополнительно TrySetDurability из AnimationEvent, звука, попадания, OnGUI или Changed: это даст двойной расход. Старый SpendRound остаётся совместимым низкоуровневым API существующего инвентаря.
- На время Changed хранилище удерживает общий mutation lock; observers видят окончательные патроны и прочность и не могут передать/изменить тот же предмет. Подписчик с исключением не отменяет уже выполненное применение и не мешает остальным наблюдателям.
- PlayerWeapons захватывает конкретный ItemStack и WeaponDefinition, закрывает повторные Attack/Reload/Equip/Unequip на время commit и выполняет применение ровно один раз. Одновременные R/ЛКМ сохраняют приоритет reload после проверки исправности/владения; проверка пустого магазина происходит при реальном выстреле.
- `PlayerWeapons.IsBusy` покрывает синхронный commit атаки, включая уведомления/шум/попадание; `ItemStorage.IsWeaponUseBusy` — прямое применение через инвентарь и его уведомления. PlayerSaveSystem проверяет оба до Save/Load, чтения файла и изменения мира. Не снимать эти guards: callback износа не должен загружать полмира посреди атаки.
- Формат 3 и SavedItem не менялись: прочность уже сохранена вместе с InstanceId и LoadedRounds. Не создавать новый save, вторую копию предмета или отдельную статистику износа на игроке. Общие проверки покрытия мира и позы остаются обязательными.

## Проверочная зона

CharacterTest, группа **T8 - Износ оружия**, рядом с прежним оружейным полигоном. Три E-консоли на X26/28/30, Z−25:

| X | Действие |
|---|---|
| 26 | Новый пистолет с прочностью 1, пустой магазин |
| 28 | Новый топор с прочностью 1 |
| 30 | 12 обычных патронов 9×19 |

Это явная тестовая выдача, каждый экземпляр имеет новый ItemStack ID; существующие вещи не чинятся и не изменяются. При нехватке места выдача целиком отказывает. Автоматической выдачи на Awake/Play/загрузке нет. Консоль использует общий Interactable/PlayerInteractor; геометрия и материал повторяют уже существующие тестовые кнопки, новые vendor-модели не нужны. Подписи — компактные напольные таблички через WorldSpacePresentationSetup.

`Assets/Editor/WeaponWearT8Setup.cs`, **Tools → Character Lab → Set Up T8 Weapon Wear (No Save)** добавляет группу один раз, не открывает другие сцены и не вызывает SaveAssets/SaveScene; занятую точку не освобождает сам. `Assets/Scripts/Weapons/WeaponWearTestConsole.cs` — только тестовая выдача. Скрипт подходит для другого предмета, заданного в Inspector, но не является общим сервисом ремонта.

Ручная проверка: E у X26 и X30 → Tab выбрать пистолет → R → два выстрела (1 → 0,5 → 0), третий запрещён, оставшиеся патроны магазина целы. E у X28 → экипировать топор → один завершённый удар (1 → 0); следующий запрещён. Новый тестовый топор: начать замах и открыть Tab до попадания — прочность 1. Перенести/выбросить/подобрать изношенное оружие; ID/прочность/магазин прежние. Для проверки F5/F9 нужен допустимый полный снимок текущей области, проверки других объектов не обходить.
