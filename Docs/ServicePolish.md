# Т11 — оформление торговли и верстака

## Поведение и настройка

Торговцы используют готовый Humanoid idle из `Bubba_The_Handyman/URP/Animations/Handyman_idle_1_animation.fbx`. Исходник не изменён: авторский `Resources/ServicePresentation/TraderIdle.controller` ссылается на настоящий клип. `ServicePresentation` назначает его только совместимому Animator торговца без собственного контроллера. Собственный controller/Avatar не заменяются; модели без Animator/Humanoid продолжают торговать. Root motion назначенного idle выключен, физический корень и авторская local-поза модели не переписываются.

Голова (при её отсутствии — грудь Humanoid) плавно доворачивается к камере собеседника: по умолчанию максимум35° в стороны,15° вверх/вниз, скорость80°/с. У торговца это работает и вне меню: ближайший живой игрок в своей сцене, радиус4м, передний сектор120° (±60°), без твёрдого препятствия между головой и камерой. За спиной, за стеной или далеко — плавный возврат к idle. Открытая сессия имеет приоритет; после закрытия взгляд продолжается, если игрок подходит под условия обычного наблюдения. Сам предметный верстак вне меню не ищет игроков.

Параметры обычного наблюдения — в ServicePresentation: включение, радиус, сектор, период поиска0,3с и слои препятствий. Глобальный поиск игроков выполняется периодически; кэшированная цель дополнительно проверяется между поисками. Не использовать Camera.main, врагов или PlayerInteractor.IsAvailable: последняя становится false при меню. Нужны активный живой FirstPersonController и его явная включённая ViewCamera. За спину голова не разворачивается даже в сессии. Runtime дополнительно ограничивает сериализованные настройки до60° yaw/30° pitch и180°/с, не доверяя одному Inspector.Range; NaN/Infinity заменяются безопасными значениями.

Накопления вращения нет: собственная поправка снимается до следующей оценки Animator и при Disable, без перезаписи чужой новой позы. Смена prefab через ServiceVisual переподключает Animator и очищает кэш взгляда. Оформление не поворачивает весь сервис, не меняет BoxCollider и не подгоняет его каждый кадр. Состояние наблюдения не сохраняется в файл мира, не включает сессию и не выдаёт доступ к торговле.

Выделить корень торговца/верстака → ServicePresentation (также вкладка «Звук» общего окна настроек): можно выключить idle, взгляд или звуки, изменить пределы/скорость и заменить профиль. Пустой профиль означает общий `Assets/Resources/ServicePresentation/Default.asset`. В профиле меняются controller, клипы успеха/отказа/ремонта, громкость и необязательная существующая группа Audio Mixer. При отсутствии профиля/клипа эффект пропускается, операция не ломается.

Звуки — короткие оригинальные заменяемые сигналы в `Assets/Audio/Generated/Services`, воспроизводимый генератор `Tools/Audio/generate_service_sounds.py`. Звук сделки/ремонта звучит после успешного TryExecute; отказ — после неуспешного явного запроса предложения или подтверждения. Проверки предпросмотра, Tick, успешный расчёт и выключенные кнопки молчат. Сервис создаёт свой один AudioSource по необходимости, без нового AudioListener. Это 2D обратная связь интерфейса, не GameplayNoise и не новый способ обнаружения игрока зомби. Длина звука ремонта не создаёт таймер/очередь: ремонт уже завершён атомарно.

Готовые исходные prefab T5Trader и T4WorkbenchSession получили ServicePresentation; варианты и связанные экземпляры наследуют компонент. Новое добавление Trader/RepairWorkbench получает его зависимостью. Для старого распакованного объекта достаточно добавить ServicePresentation вручную. Замена модели остаётся прежней — ServiceVisual, без назначения окон и звуков на каждый визуальный prefab.

## Удобство окон

- Торговля: у товаров и своего рюкзака независимые фильтры категорий и сортировка по имени, возрастанию цены или убыванию доли прочности. Неподдерживаемые/неоценённые товары при сортировке цены идут в конце.
- Верстак: прежние фильтры Все/Оружие/Снаряжение плюс имя/прочность. Денежные цены других торговцев сюда не подмешиваются: ремонт только материалами.
- Выбранный экземпляр подсвечен. Сортировка/фильтр меняют только отображение, не порядок ItemStorage, выбранную ссылку или котировку. Равные строки упорядочиваются по имени, стабильному InstanceId и исходному слоту; одинаковые предметы не сливаются.
- Ниже основных действий — сравнение с собственными экземплярами того же ItemDefinition: прочность/разница, магазин. В торговле — справочные Buy/Sell цены активного профиля с учётом состояния/патронов; на верстаке — материалы до полного восстановления. Это не предложение новой операции. Не добавлять сравнение урона/защиты, если таких механик у типа нет.
- Детали прокручиваются, основные кнопки идут перед сравнением. Escape/закрытие, проверки доступа и блокировки управления Т4 прежние; мир продолжает работать.

## Контракт второго разработчика и ИИ

`ServicePresentation`/`ServicePresentationProfile` — необязательное оформление, не экономический сервис. `PlayerServiceSession.ReportOperationResult(bool)` вызывается UI один раз после явной операции; никаких списаний/выдачи/изменения прочности в этом пути нет. Backend TradeService/RepairService остаётся единственным исполнителем и последней проверкой. Не озвучивать каждый отказ TryQuote при OnGUI/Tick, иначе интерфейс будет звучать каждый кадр. Повторные сигналы дополнительно ограничены интервалом0,12с.

Не присваивать controller исходному vendor-prefab и не сбрасывать Transform ради idle. Чужой назначенный контроллер сохранять. Компонент возвращает только назначенный им controller, если он всё ещё используется; внешнюю замену не стирает. При внешней смене controller владение передаётся внешнему коду вместе с текущим root-motion: старое значение applyRootMotion поверх чужого controller не восстанавливается. При Disable/смерти/WorldStateRestored прекращает звук/взгляд и освобождает свою анимацию. RuntimeInitialize сбрасывает transient-состояние и подписки при Play без Domain/Scene Reload. Не сохранять анимационную позу, звук или фокус головы в общем формате мира.

`ItemListPresentation` — readonly-проекция ссылок для существующих IMGUI окон, не второй инвентарь. Не изменять quantity/ID/прочность при сортировке или сравнении, не копировать оригинал ради сделки, не подменять старое предложение молча. Все прежние locks/SessionVersion/инвалидация действуют.

`ServicePresentationT11Setup.Run` / Tools → Character Lab → Set Up T11 Service Presentation (No Scene Save) создаёт только недостающие общие assets/компоненты исходных prefab. Исходные prefab сохраняет адресно, включая автоматически добавленный Unity новый RequireComponent: наличие компонента лишь в загруженной памяти не доказывает запись на диск. Авторские профили не сбрасывает, vendor imports и сцены не сохраняет. Скрипты общих настроек расширены без второго источника значений. После дальнейших изменений обновлять AGENTS.md и этот документ.

Т12 (пополнение/наценки/расширенная экономика) только по отдельному запросу. Слоты брони, улучшения, ремонтная очередь и новое состояние сохранений в Т11 не добавляются.

После удаления стены цель снова приобретается. Явная сессия через настоящее E работает при выключенном ambient-переключателе; после Escape обычное наблюдение продолжается. Отчёты/вид — `_CodexRecovery/TraderLook-20261020`; экономика и сцена пользователя не изменялись. Ниже сохранены исходные проверки Т11.
