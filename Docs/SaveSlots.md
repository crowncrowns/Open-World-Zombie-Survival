# CM-05 — автосохранение, ручные слоты и меню

Т13: [TradeRepairIntegration.md](TradeRepairIntegration.md). Торговля/ремонт/таймеры входят в прежний общий формат3; проверены cold-process, повторный no-reload Play, corrupt-file отказ и явный backup с экономикой. Ограничения streaming/аварийного выхода сохраняются.

`PlayerSaveSystem` остаётся единственным сборщиком/валидатором/загрузчиком общего снимка CM-04. Новые `PlayerSaveSlots` и `PlayerSaveMenu` находятся на `CharacterTestPlayer.prefab`. Номер формата **3** сохранён: это новые способы выбора файла того же снимка, а не отдельное сохранение денег или вещей. Контракты мира — [WorldSaving.md](WorldSaving.md), хотбара — [Hotbar.md](Hotbar.md).

## Управление и настройки

- **F5/F9** — прежний отдельный быстрый файл `character-stage11.json`.
- **F6** — меню файлов: быстрый, ручные и автослоты, дата/время и сцена, явная загрузка и «Продолжить последнее». F6/Esc закрывают окно. Меню доступно после смерти; загрузка выполняется только по команде, при запуске ничего не загружается.
- По умолчанию **3 ручных** файла `character-stage11-manual-1.json`… и **3 автоматических** `character-stage11-auto-1.json`… в `Application.persistentDataPath`. Смена базового `fileName` меняет семейство файлов, не переносит старые. Уменьшение числа слотов скрывает лишние файлы, не удаляет их; увеличение возвращает доступ.
- Автосохранение включено, интервал **300 секунд активного игрового времени**. `Time.timeScale=0` и смерть останавливают отсчёт; рюкзак не останавливает мир. Меню F6 блокирует управление, но не время и не урон NPC. Окна инвентаря/дерева нельзя открыть поверх него.
- Настройки в **Tools → Zombie Survival → Настройки персонажа и зомби → Потребности / сохранение**: включение, интервал, количества слотов, пауза повторной попытки (по умолчанию **30 с**), клавиши меню. Это настоящие поля компонентов, не второй источник значений.

По достижении интервала существует **один** ожидающий запрос. В воздухе, паркуре, замахе/перезарядке и открытом меню файлов он ждёт безопасного момента; затем пишет один снимок. После смерти ожидающий запрос не записывает файл. Успешное ручное/быстрое/автоматическое сохранение или загрузка начинают интервал заново. Отключение автосохранения очищает ожидание; повторное включение начинает новый интервал.

Ротация: первый пустой автослот, затем самый старый по сохранённому UTC. Повреждённый файл без читаемых метаданных считается кандидатом на замену раньше исправных. Выбор делается заново на попытку, поэтому новый процесс продолжает ротацию по диску, без отдельного файла счётчика. Ручные и быстрый файлы в ротацию не входят.

## API и ошибки — для разработчика и ИИ

`Assets/Scripts/Persistence`:

| API | Контракт |
| --- | --- |
| `PlayerSaveSystem.CanSaveNow(out reason)` | Дешёвая проверка жизни/земли/действия/паузы. Не заменяет полную проверку участников мира. |
| `TrySave()` / `TryLoad()` | Обратно совместимые команды быстрого файла. |
| `TrySaveSlot(kind,index)` / `TryLoadSlot(kind,index,backup=false)` | Тот же полный снимок и подготовка CM-04, индексы с нуля. Не меняют сериализованный fileName. |
| `SlotPath(kind,index)` | Только контролируемые суффиксы, без пользовательского пути к произвольному файлу. |
| `InspectSlot(kind,index,backup=false)` | Проверяет размер, конверт/SHA-256, версию и сцену для списка; **не** проверяет всё состояние мира/каталог/свободную позу. `Readable` не гарантирует успешную загрузку. |
| `SaveCompleted`, `LoadCompleted` | Уведомления после успешной операции; планировщик сбрасывает интервал. Подписчики только наблюдают, не запускают вложенную загрузку. |
| `PlayerSaveSlots.Pending`, `AutoStatus`, `InspectSlots()`, `TryContinue()` | Ожидание/статус/список и явная загрузка самого нового читаемого файла. Ошибка полной загрузки не вызывает скрытый перебор старых файлов. |

Все записи используют прежние `.tmp → File.Replace` и `.bak`. Ошибка проверки мира/диска видна в HUD/меню; автоповтор ограничен `retrySeconds`, а не вызывается каждый кадр. `.tmp` не является кандидатом на продолжение. Повреждённый основной файл **не** подменяется резервом молча: отдельная кнопка **«Загрузить резерв .bak»** читает его тем же полным загрузчиком, не переписывая основной файл. Следующее успешное сохранение создаёт актуальный основной снимок.

Сборка снимка, Unity API и запись синхронны на главном потоке; для большого мира нужно измерить время и отдельно выносить только готовые неизменяемые байты в фон. Выход, аварийное закрытие, checkpoints и streaming не запускают новых сохранений. Это CM-05 для одной области CM-04, не система межсценового streaming; профили подключены Т5–Т13.

## Подключение и ручная проверка

Существующий игрок настроен. Идемпотентное подключение на личном полигоне — **Tools → Character Lab → Set Up CM05 Save Slots**, проверка — **Check CM05 Save Slots**. Setup не меняет допустимость предметов в хотбаре и выбранные значения слотов. В новом игроке нужны прежний PlayerSaveSystem/реестр CM-04, PlayerSaveSlots и PlayerSaveMenu; не ставить эти компоненты на NPC.

1. F5, F6, записать два ручных слота с разными деньгами/предметами. У каждого видны дата и сцена. Загрузить нужный, затем явно продолжить последний; повторить после нового запуска Unity.
2. Временно уменьшить интервал в Inspector до нескольких секунд. Дождаться заполнения 3 автослотов и замены самого старого; быстрый/ручные файлы не меняются. Возвратить 300 с.
3. Пересечь срок в прыжке/паркуре/перезарядке: увидеть ожидание, после завершения — один снимок. Пауза останавливает время, рюкзак продолжает, F6 задерживает запись. После смерти файлы остаются прежними; загрузка из F6 разрешена.
4. Повредить копию основного файла вне игры: загрузка отказывает без изменения живых предметов/рублей, резерв доступен отдельной кнопкой. Не проверять на единственном пользовательском файле.
5. Ошибка временной записи/неподключённый Wallet-адаптер: видимый отказ, старый рабочий файл цел, повтор только после задержки. Проверить F6/Esc, Tab/K и удерживаемые ЛКМ/ПКМ при выходе из меню — без непреднамеренного использования вещи.

Изменённые файлы: PlayerSaveSystem, новые SaveSlotInfo/PlayerSaveSlots/PlayerSaveMenu, Editor SaveSlotsSetup/SaveSlotsValidation, ActorSettingsWindow, префаб игрока и CharacterTest. Связанный автоподбор меняет ItemDefinition/WorldItem/PlayerHotbar/PlayerInventory и авторские типы вещей; его контракт — Hotbar.md. Vendor-ресурсы и SampleScene не меняются.
