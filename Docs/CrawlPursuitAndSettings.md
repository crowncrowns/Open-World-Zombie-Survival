# Ползущий преследователь, тихий шаг и настройки актёров

## Настройки без поиска по всем компонентам

Выдели игрока или зомби и открой **Tools → Zombie Survival → Настройки персонажа и зомби**. Можно выделить дочернюю кость или модель: окно поднимется к ActorIdentity. Кнопка открытия также находится в Inspector компонента ActorIdentity.

Вкладки: **Общие**, **Движение**, **Паркур**, **Скрытность / ИИ**, **Внешность**, **Инвентарь**, **Звук**. Это редактор настоящих сериализованных компонентов, а не второй набор параметров. Для постоянной настройки всех зомби выбирай `ZombieMaleActor.prefab` в Project; для конкретного зомби — экземпляр сцены. Изменения в Play временные. Подсказки к параметрам игрока и AI переведены на русский.

**Общие → Принадлежность и отношения**:

- Фракция — кто этот актёр. **Выжившие**: игрок/люди. **Заражённые**: зомби. Также есть нейтральные и животные.
- Кого считает врагом — фракции, на которые этот актёр имеет право охотиться. У зомби отмечены выжившие; у игрока — заражённые и животные. Два зомби одной фракции друг на друга не охотятся.
- Отношения направленные: настройка зомби определяет поведение зомби, настройка NPC — поведение NPC. Прямой вызов Health.ApplyDamage для окружения/тестовой консоли не является системой отношений; стандартные атаки проверяют CombatTarget.CanBeTargetedBy.

Не менять значения enum и номера битов при переводе: они уже сериализованы в префабах. Русские названия заданы InspectorName, программные имена сохранены.

## Ползание зомби

Реальное укрытие с крышей высотой 0,90 м находится в восточной зоне: `(66, 0, -20)`. Покажись зомби, подойди к входу и нажми Z, затем ползи под крышу. Зомби подходит к входу стоя. Только если перед ним стоячая капсула не проходит, а низкая проходит, он опускается на четвереньки, уменьшает физическую капсулу/высоту глаз и строит путь через низкий проход. На открытом месте приседание или положение лёжа игрока не заставляет зомби ложиться. Процедурная Humanoid-поза служит временной заменой отдельного клипа падения и ползания. Её можно настроить во вкладке Внешность; позднее заменить клипами, сохранив навигацию и правила обнаружения.

`EnemyBrain` разрешает переход только для **уже виденной цели**, в пределах короткой памяти о зрительном контакте и дистанции входа. Дополнительно проверяется открытый луч от низкой точки глаз до цели. Сплошная стена не раскрывает игрока. Для замеченного входа хранится снимок позиции на ограниченное время: это позволяет подойти к крыше до перехода в ползание, не отслеживая скрытый Transform. Crawl Start Distance задаёт расстояние перехода перед препятствием, Entry Memory Seconds — время подхода к замеченному входу. Игрок, который спрятался до встречи, остаётся скрытым. Шум сообщает область с погрешностью, а не ссылку на Transform. Если низкий зрительный контакт тоже потерян, поиск идёт возле последней известной позиции.

`EnemyCrawlPursuit` не зависит от FirstPersonController: низкая поза цели определяется её Collider bounds. Он переключает **тип агента**, капсулу, скорость и точку глаз; встать можно только при свободном объёме и доступном обычном NavMesh. Нельзя считать уменьшение `NavMeshAgent.height` достаточной настройкой: обычный NavMesh уже исключает тоннель при запекании.

Для нового уровня нужны две NavMeshSurface: обычная Humanoid и низкая **Humanoid Crawl** (высота 0,65 м, радиус 0,30 м). Обе поверхности должны быть запечены и загружены. `Crawl Agent Type` префаба ссылается на этот тип из `ProjectSettings/NavMeshAreas.asset`. Не создавай новый случайный ID вручную. Сохранять в git проектный профиль, два NavMeshData и ссылки сцены вместе. Внешность и движущиеся актёры исключаются из bake через NavMeshModifier. Двери используют carving для обеих поверхностей.

`HumanoidGrounding` вызывает HumanoidCrawlPose до стоячего IK, чтобы стоячие ноги не перетирали ползание. На Animator должна быть включена IK Pass у базового слоя. Не двигать навигационный корень из анимации, root motion остаётся выключенным. Новый монстр с нечеловеческим ригом может использовать EnemyCrawlPursuit с собственной визуализацией.

Проверить: видимый вход → ползание под крышей; крыша блокирует вставание; после выхода и подъёма цели возвращается стоячее преследование; скрытый заранее игрок не раскрывается; удар проверяет низкую точку и препятствия; смерть отменяет удар/движение; тестовый сброс возвращает обычную позу.

## Слух на 360° и HUD

**Alt** (левый или правый) — тихий шаг 1,5 м/с, громкость 0,3 и радиус до 6 м. Имеет приоритет над Shift. В приседании/ползании сохраняются их собственные настройки. Обычная ходьба — громкость 1 и радиус до 18 м; бег — 3 и до 28 м; приседание — 0,2 / 5 м; ползание — 0,08 / 3 м. Эти пределы не гарантируют обнаружение: есть расстояние, препятствия и порог слуха конкретного монстра.

Слух не использует Field Of View: шаги слышны сзади. `Investigation Speed` отделена от медленного Patrol Speed: зомби разворачивается к услышанной области и идёт проверять её быстрее патруля. `Hearing Threshold` меньше — слух лучше; `Hearing Reference Distance` больше — звук медленнее затухает. `React To Friendly Noise` обычно выключена. Подкрадывание не означает полную бесшумность вплотную.

Вверху HUD есть **ШУМ**, полоса, тип движения и предельный радиус последнего игрового события. 100% соответствует громкости 4, это **не вероятность обнаружения**. После короткого времени без нового шума индикатор возвращается к нулю. UI читает тот же PlayerNoiseEmitter, который отправляет события зомби, без отдельной симуляции звуков. AudioSource для игрового слуха не нужен.


Звуки шагов и голоса подключены отдельно от обнаружения: [ActorAudio.md](ActorAudio.md).
