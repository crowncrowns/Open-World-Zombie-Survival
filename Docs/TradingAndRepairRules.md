# Т1: категории предметов, рубли и правила ремонта

Статус: Т1 завершён как спецификация. Т2 реализовал категории и состояние прочности в существующем инвентаре; торговля, кошелёк, износ и верстак ещё не реализованы. Пользователь выбрал рубли отдельным балансом и ремонт только материалами. Остальные стартовые правила ниже — принятые рабочие настройки первой версии, изменяемые данными на следующих этапах.

Связанные документы: [план Т1–Т13](TradingAndWorkbenchPlan.md), [предметы](Inventory.md), [оружие](Weapons.md), [взаимодействие](Interaction.md), [общие актёры](ActorIntegration.md).

## 1. Категории

У типа предмета одна основная категория; подкатегория уточняет его назначение. Ни название предмета, ни имя GameObject не определяют торговлю. Для расширяемости используются стабильные идентификаторы данных, а не порядок переведённых названий. У новых категорий/профилей ID не меняется при переименовании в интерфейсе.

| Основная категория | Подкатегории / примеры | Учёт экземпляров | Ремонт в первой версии |
| --- | --- | --- | --- |
| Оружие | Огнестрельное; ближний бой | По 1 в слоте, уникальный ID, магазин и прочность | Да, если назначен ремонтный профиль |
| Патроны | Тип боеприпаса, например 9×19 | Стопки по лимиту типа | Нет |
| Снаряжение | Рюкзак; броня; тактический жилет; одежда | По 1 в слоте, уникальный ID и прочность | Да, если назначен ремонтный профиль |
| Еда | Консервы и другие продукты | Стопки по лимиту типа | Нет; свежесть не равна прочности и пока не добавляется |
| Медицина | Бинты, аптечки и другие средства | Стопки по лимиту типа | Нет |
| Материалы | Ткань, оружейные детали, бронематериалы | Стопки по лимиту типа | Нет; расходуются рецептом ремонта |

Подкатегории снаряжения не обещают уже реализованные слоты/эффекты экипировки. Одежда подготовлена в классификации, но создавать её контент до отдельного задания не требуется. Инструменты, квестовые предметы, бартер и прочие категории не добавляются автоматически в этот этап.

Тип определяет MaxStack; для оружия и изнашиваемого снаряжения он равен 1. Прочность одного экземпляра не записывается в общий ItemDefinition/WeaponDefinition. Будущий экземпляр сохраняет один и тот же ID, прочность, магазин и принадлежность при переносе, продаже и ремонте.

## 2. Три профиля торговца

Предлагаемые постоянные ID профилей: `weapons_ammo`, `equipment`, `food_medicine`. Это данные каталога; код одного Trader одинаков для всех трёх.

| Профиль | Продаёт / выкупает по умолчанию | Дополнительные материалы |
| --- | --- | --- |
| Оружие и патроны | Оружие обеих подкатегорий, патроны | Оружейные детали |
| Снаряжение | Рюкзаки, броня, жилеты; одежда при появлении | Ткань и бронематериалы |
| Еда и медицина | Еда, медицина | Ткань может быть добавлена явно в каталог |

Категории задают исходный фильтр выкупа, но конкретный ассортимент и исключения задаются самим профилем. Один тип предмета может входить в несколько каталогов: для ткани не создавать отдельные несовместимые предметы «для медика» и «для снаряжения». Отдельные списки продажи/выкупа позволяют расширять профиль без switch по имени категории в UI.

Торговец стоит на месте. Анимация ожидания необязательна и не влияет на доступность функций. Компонент на новом NPC с выбранным профилем использует общие сервисы и окно; не требует кода под каждую модель. Профили по умолчанию поставляются вместе с системой, а не собираются заново для каждого NPC.

Смена профиля во время игры сразу меняет ассортимент/правила выкупа. Текущие выбор и котировка отменяются. У каждого экземпляра Trader отдельные остатки по ID профиля; возврат к профилю восстанавливает его прежнее состояние, а не начальный запас. Общий бюджет этого торговца сохраняется между профилями. Проданные игроком экземпляры не исчезают при переключении и не пересоздаются как новые.

## 3. Валюта — подтверждено пользователем

- Единственная валюта первой версии — **рубли**, отображение `1 250 ₽`.
- Деньги находятся в отдельном Wallet: не занимают слот и не имеют веса. Предметов-купюр в инвентаре нет.
- Учёт целыми рублями, без копеек; будущий код использует целочисленную арифметику с проверкой диапазона/переполнения, без float для баланса.
- Отрицательный баланс, кредит, обмен валют и бартер не поддерживаются. Нулевая цена возможна только как явная настройка, отрицательная цена недопустима.
- Начальный баланс игрока настраивается; безопасное значение по умолчанию — 0. Тестовые деньги выдаёт явная консоль/настройка полигона, а не повторное открытие торговли или смена NPC.
- Конечный бюджет каждого торговца и бесконечный тестовый режим выбираются явно в профиле/настройках экземпляра. Смена специализации бюджет не пополняет.
- Цены покупки и продажи задаются данными; продажа вещи обратно тому же торговцу без изменений её состояния не должна давать прибыль. Численные цены и начальные суммы баланса подобрать на Т3/Т6 по фактическому набору товаров.

Цена конкретного оружия должна иметь явную политику учёта патронов в магазине: на Т6 либо считать их стоимость, либо потребовать разгрузку перед продажей. Запрещено молча удалять или бесплатно создавать патроны. Это решение реализации сделки, а не добавление второго запаса боеприпасов.

## 4. Прочность

- Состояние показывается в процентах 0–100%. Для первого прототипа ремонтируемые типы получают максимум 100 единиц; интерфейс/API рассчитывают долю от максимума, чтобы позже менять его данными.
- Новый экземпляр создаётся полностью исправным, если явно не задано другое начальное состояние. Старые предметы после добавления полей должны мигрировать в исправное состояние, а не автоматически становиться сломанными.
- Обычная прочность относится к конкретному оружию/снаряжению. Патроны, материалы, еда и медицина её не имеют.
- Нулевая прочность не удаляет предмет; он остаётся в инвентаре и допускает ремонт. При подключении реального износа на Т8 сломанное оружие не атакует, сломанная броня не даёт защиты. Реализацию этих ограничений не добавлять на этапе Т1.
- Поломка рюкзака/жилета никогда не удаляет содержимое, слоты и вещи. Конкретные эффекты износа переносимого снаряжения согласовать при добавлении его реальных функций; до этого состояние ремонтируется без выдуманных бонусов/штрафов. Одежда не добавляет тепло/защиту автоматически.
- Источники и темп износа подключаются на Т8. Само открытие меню, ходьба с вещью в рюкзаке и перенос вещи её не изнашивают.

## 5. Ремонт только материалами — подтверждено пользователем

Деньги на верстаке не списываются. Материалы можно купить у торговца, но это отдельная сделка. Ремонт не зависит от баланса Wallet.

Первая версия ремонтирует выбранный экземпляр **до его текущего максимума**, мгновенно после подтверждения. Максимальная прочность не уменьшается, количество ремонтов не ограничено; нет очереди, случайной неудачи, времени изготовления или скрытой платы. Расширения возможны отдельным заданием.

Начальные ремонтные профили и тестовые рецепты полного восстановления от 0 до 100:

| Профиль | Что ремонтирует | Базовый расход при 0 → 100 |
| --- | --- | --- |
| Оружейный | Огнестрельное и оружие ближнего боя | 4 оружейные детали |
| Текстильный | Рюкзак, одежда, незащищённый жилет | 4 ткани |
| Броневой | Броня, защищённый тактический жилет | 4 бронематериала + 2 ткани |

Это начальные **тестовые** коэффициенты для будущего Т9, не окончательный баланс. Конкретный тип может заменить рецепт; защищённый/незащищённый жилет различается назначенным профилем, а не поиском слова в названии. Тип без разрешения ремонта/профиля не ремонтируется.

Для каждого материала с базовым расходом B:

`нужно = ceil(B × (максимум − текущая прочность) / максимум)`.

При нулевом повреждении расход равен 0 и действие недоступно. Любое положительное повреждение расходует минимум 1 единицу каждого материала с B > 0. Округление всегда показывается в предварительном расчёте до нажатия. Проверять корректность максимума/рецепта; отрицательные количества и пустой бесплатный рецепт повреждённой вещи считаются ошибкой настройки.

Примеры оружейного профиля: 50 → 100 стоит 2 детали; 75 → 100 стоит 1; 99 → 100 тоже стоит 1 из-за минимальной единицы ресурса. Пример брони: 50 → 100 стоит 2 бронематериала и 1 ткань. Вещь при 0 может полностью восстановиться, если хватает материалов.

Материалы первой версии берутся только из доступного ItemStorage самого игрока; удалённые ящики не используются. Ремонт не требует отдельного инструмента/ремнабора. Надетые вещи подключаются через общую систему экипировки, когда она реализована; ID и владение не дублируются.

## 6. Доступ к верстаку и безопасность операций

Подход к объекту, наведение и E используют существующие PlayerInteractor/Interactable, их дальность и проверку препятствий. Верстак не чинит автоматически при приближении. Меню показывает предмет, состояние, полный список нужных материалов и результат; деньги в стоимость ремонта не входят.

В момент подтверждения повторно проверять живого игрока, активную сессию, физическую доступность верстака, владение именно этим экземпляром, актуальную прочность и ресурсы. Списание материалов и восстановление выполняются одной операцией до уведомлений UI: либо весь ремонт, либо никаких изменений. Двойное нажатие, смерть или закрытие окна не должны списывать второй рецепт. Предмет не заменяется новым; магазин и ID сохраняются.

При полном состоянии, отсутствии материалов, неподдерживаемом предмете или потере доступа кнопка «Ремонт» недоступна с причиной. «Улучшить» всегда выключена и ничего не списывает. После смерти/выключения верстака/потери доступа сессия закрывается по общему контракту; мир не ставится на паузу.

## 8. Инструкции для второго разработчика и его ИИ

Т1 изменяет только спецификацию. Т2 выполнен: классификация и состояние экземпляров с миграцией реализованы. Следующий Т3 — только по отдельному заданию. Не реализовывать деньги/продажу/верстак внутри FirstPersonController, PlayerWeapons или кнопок UI. Не заводить вторую модель инвентаря/урона и не менять выбранные пользователем рубли/материальный ремонт без нового запроса.

Профили, категория и стоимость относятся к типам/данным; живая прочность, магазин и ID — экземпляру; деньги — Wallet; остатки — конкретному Trader и его профилю. Проверки вместимости и переноса остаются в ItemStorage. Т2 обобщил состояние для оружия и снаряжения: Copy — non-transferable read-only snapshot; перенос оригинала выполняют TransferTo/TryExtract/TryAddStack/WorldItem.Initialize. Текущая прочность относится к ItemStack, maximum/repairable/profileId — к ItemDefinition. Профиль пока только ID, без рецепта/цены.

После Т2 проверить: два экземпляра одного типа с разной прочностью; перенос рюкзак → ящик → мир → обратно; сохранность ID/магазина/прочности; отсутствие стека у снаряжения; старые предметы исправны; прежние лимиты патронов/еды/ткани сохранены. После Т9 добавить проверки приведённых рецептов, отказа при нехватке материалов, полного ремонта с нулевым балансом рублей и недоступного «Улучшить».

Проверка Т1: исходные пять ItemDefinition и текущие контракты инвентаря/оружия прочитаны; ID и лимиты сверены. Код и сцены не изменялись, Play-проверок не было. После каждого этапа обновлять AGENTS.md, этот документ при изменении правил и профильные Docs с фактическими API/путями/проверками.
