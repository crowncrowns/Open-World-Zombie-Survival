# Git в Windows: длинные пути и восстановление обновления

## Итог 19.10.2026

Обновление завершено обычным fast-forward: main перешёл с `99fe3c77d47bd64e4421bf1b1063dba798624283` на `799b3c93248f5c7bc307da4a178bc609cb4f5833` (пять входящих коммитов). HEAD и origin/main совпадают. Новые коммиты и push не выполнялись.

Причина первоначального отказа GitHub Desktop — длинные пути во вложенном `work/KursHub/UnityProject/Assets/Kevin Iglesias/...`. Windows LongPathsEnabled уже равен 1; для этого клона включён `core.longpaths=true`. Это настройка `.git/config`, она не переносится коммитом. При аналогичной ошибке в другом клоне применить:

```powershell
git config --local core.longpaths true
git config --show-origin --get core.longpaths
```

Основание: [Git for Windows: long paths](https://gitforwindows.org/git-cannot-create-a-file-or-directory-with-a-long-path.html).

## Что сохранено и как завершено

До восстановления main отставал на пять коммитов; индекс оставался исходным, а рабочая копия содержала частично распакованное обновление: 90 изменённых отслеживаемых файлов, 1 644 новых неигнорируемых файла, а также входящие файлы в игнорируемых каталогах. Конфликтных записей индекса и MERGE_HEAD не было.

Резервная копия вне репозитория: `S:\Games\Unity Projects\_CodexRecovery\OpenWorld-20261019-005656`. Сохранены 6 486 существовавших файлов, 2 992 525 916 байт, включая игнорируемые файлы на входящих путях. Каждый файл проверен SHA-256. Отдельно сохранены индекс, ссылки, конфигурация, статусы и патчи. Library/Temp и прочие игнорируемые каталоги, не затрагиваемые обновлением, не являются частью этой выборочной копии и не изменялись.

Сравнение с учётом Git/LFS-фильтров: 6 484 файла уже совпадали с входящим коммитом. Уникальны только добавленная инструкция Docs/GitWindowsPaths.md и её ссылка в AGENTS.md. Для AGENTS выполнено чистое трёхстороннее объединение. Все 42 изменённых GUID в .meta соответствовали входящим версиям; старые GUID поверх них не возвращались.

После повторной проверки исходные файлы перемещены в quarantine рядом с неизменяемой копией files. Только 90 сохранённых отслеживаемых путей восстановлены из исходного HEAD. При первой попытке fast-forward Git отказал из-за устаревших записей индекса после восстановления файлов; операция остановлена. Содержимое всех 90 путей повторно сверено по Git blob hash с исходным HEAD, записи индекса обновлены без изменения его дерева; чистая база подтверждена. Затем обычный `merge --ff-only` завершился успешно. Локальные две правки документации возвращены. Discard/reset --hard/clean не применялись; история не переписывалась.

Локальная страховочная ссылка: `refs/recovery/pre-update-OpenWorld-20261019-005656`, указывает на исходный HEAD. Она не отправлялась на сервер.

## Проверки и инструкции следующему разработчику / ИИ

- Все 6 398 добавленных входящим обновлением файлов присутствуют. Проверены четыре наиболее длинных пути, включая три из первоначальной ошибки: содержимое соответствует входящим Git blob.
- SHA-256 всех 2 984 LFS-файлов рабочей копии соответствует указателям; проверены также 1 406 уникальных объектов локального LFS-кэша. Файлы представлены содержимым, а не текстовыми LFS-указателями.
- Индекс соответствует дереву входящего коммита. main и origin/main имеют расхождение 0/0. Единственные незакоммиченные файлы после работы — AGENTS.md и Docs/GitWindowsPaths.md с этими инструкциями.
- Подробные отчёты: snapshot.json, classification.json, operation.jsonl, index-refresh-verified.txt, result.json, verification.json в резервной папке. files содержит неизменённые копии до восстановления; quarantine — перемещённые оригиналы. Не возвращать всю копию поверх обновлённого проекта: большинство её файлов уже является частью нового коммита. Сначала сравнить конкретный путь и его происхождение.
- Не удалять резервную папку до подтверждения пользователем. Следующие изменения выполнять поверх нового HEAD, сохраняя .meta/GUID. Настройку longpaths проверять в каждом клоне отдельно; не переименовывать ассеты и .meta ради ограничения пути.
- Проверки этой операции относятся к Git и целостности файлов. Unity не запускалась, компиляция и Play после обновления здесь не проверялись. Известные ограничения входящих механик читать в соответствующих Docs; завершение Git-обновления не означает их исправление.
