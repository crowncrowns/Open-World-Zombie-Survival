# Хотбар и использование предметов — CM-01–CM-03

Реализован совместно с этапом 12. Назначения — только ссылки на `ItemStack.InstanceId` **собственного** `ItemStorage`: второго инвентаря и копий предметов нет. Новые настройки снабжены русскими названиями и Tooltip. Общая очередь — [Core Mechanics](CoreMechanics.md), сохранения — [CharacterSurvivalAndSaving](CharacterSurvivalAndSaving.md).

## Автоподбор и допустимость типа

В `ItemDefinition` добавлен **«Можно в хотбар»** (`AllowInHotbar`), с русским Tooltip. Новый тип по умолчанию запрещён, автор включает его явно. У существующих пистолета/топора/консервов/воды/аптечки включён; у патронов, ткани и тестового рюкзака выключен. Редактировать ассет типа напрямую либо через вкладку **Инвентарь** общего окна настроек. Категория не переопределяет явный флаг: будущий особый предмет допускается данными без изменения кода. Разрешение не создаёт эффекта использования само по себе.

После успешного подбора `WorldItem` с пола полученные стопки занимают первые свободные слоты. Занятые назначения и выбранный индекс не заменяются; полный хотбар оставляет вещь в обычном рюкзаке. Если выбранный слот был пустым и заполнился, его обычное содержимое/оружие становится активным. Повторный pickup, объединившийся с уже назначенной стопкой, не создаёт второго назначения. При overflow назначаются реально получившие количество остатки, пока есть место.

Контракт: WorldItem сохраняет количества по InstanceId ДО TryAddStack/TryAddAll; только после успеха вызывает `PlayerHotbar.CompleteWorldPickup`. Сравнение ПОСЛЕ переноса определяет получившие количество ID, включая merge с сохранением ID принимающей стопки. Не угадывать полученный экземпляр по имени/первой вещи того же типа; не пересоздавать оружие и его магазин. Неудачный pickup ничего не назначает.

`Assign`, экипировка через хотбар, `GetAssignedItem`, очистка и восстановление назначений учитывают AllowInHotbar. Ручная кнопка «Назначить» недоступна запрещённому типу. Если дизайнер запретил ранее назначенный тип, сохранённая ссылка очищается при восстановлении/перепроверке, сама вещь остаётся в рюкзаке. Автозаполнение не вызывается из Changed, загрузки, торговли, переноса из ящика или обычной выдачи TryAddAll; эти системы сохраняют прежний контракт.

Проверять: E-подбор еды/оружия; патроны не занимают слот; merge с назначенной/неназначенной стопкой; переполнение в новую стопку; полный хотбар и полный рюкзак; разрешение/запрет в ассете; старое запрещённое назначение при F9; частичный Q → E сохраняет ID/количество и не дублирует привязку. Сохранения/слоты CM-05 — [SaveSlots.md](SaveSlots.md).
## Управление

Актуальная привязка с 24.10: **G — выброс**, **F — взаимодействие**, удержание **Q/E — выглядывание с оружием**. Прежние Q/E в исторических проверках ниже не являются текущей схемой управления; [PlayerPeeking.md](PlayerPeeking.md).

По умолчанию пять слотов. В Tab выберите предмет своего рюкзака, затем «Назначить» под нужным быстрым слотом. Назначить можно и в пустой слот; существующее назначение заменяется. Нажатие названия слота выбирает его; × очищает только ссылку, предмет остаётся в рюкзаке. Одна вещь не назначается дважды: новое назначение переносит ссылку. Предмет открытого ящика нельзя назначить, пока он не перенесён в свой рюкзак.

- **1–5** выбирают конкретный слот. Пустой слот освобождает руки.
- **Колесо** и **D-pad влево/вправо** циклически проходят слоты, включая пустые. Верх колеса выбирает предыдущий слот; направление редактируется. При открытом рюкзаке или дереве развития колесо относится к интерфейсу.
- **ЛКМ** применяет выбранную вещь: оружие стреляет/ударяет, еда/вода употребляется по одной единице на новое нажатие. Полные показатели не расходуют еду/воду. Автоматическое оружие сохраняет свой режим стрельбы.
- **ПКМ** прицеливает огнестрельное оружие. У обычной еды/воды вторичного действия пока нет, предмет не расходуется.
- **G** выбрасывает **одну** единицу активной стопки; индивидуальную вещь — целиком. Выброс всей стопки остаётся в рюкзаке. Если нет безопасного места, количество и назначение сохраняются.
- **R** — прежняя перезарядка живому / возрождение мёртвому. E — прежнее взаимодействие с миром.

«Экипировать» у оружия в рюкзаке использует то же назначение: выбирает существующий быстрый слот вещи либо заменяет назначение текущего слота. Это не позволяет стрелять старым пистолетом, пока выбранная вещь — вода или пустой слот.

При активном хотбаре старая отдельная инструкция оружия скрыта. Нижний блок боезапаса показывается только для выбранного оружия: у воды, еды и пустого слота нет дублирующей надписи «Оружие не выбрано». Название и выбор обычной вещи уже видны в хотбаре.

Количество слотов можно настроить от 1 до 10. Только первые пять получают цифровые клавиши; остальные выбираются колесом/D-pad и кнопками рюкзака. Уменьшение количества удаляет лишние **назначения**, не вещи. Стартовые назначения пусты: настройка не создаёт предметы и не раздаёт оружие.

## Контракты для другого разработчика и ИИ

`Assets/Scripts/Inventory/PlayerHotbar.cs` хранит модель назначений, HUD и маршрутизирует команды. `PlayerInventory` остаётся окном/операциями рюкзака. `WorldItemDropService` выделен из старого Drop: обе кнопки рюкзака и Q используют одну проверку пути/земли/свободного места и перенос оригинала через `TryExtract` → `WorldItem.Initialize`. При отказе и rollback исходная ссылка восстанавливается. Не заменять этот путь созданием нового ItemStack/TryAddAll.

Публичный API хотбара:

| API | Назначение |
| --- | --- |
| `SlotCount`, `SelectedIndex`, `ActiveStack`, `Storage` | Текущий размер, выбор и живая ссылка принадлежащей игроку вещи. |
| `GetAssignedItem(hotbarSlot)` | Разрешает ID в текущем собственном хранилище, а не по номеру inventory-слота/типу. |
| `Assign(hotbarSlot, inventorySlot)`, `Clear(hotbarSlot)`, `Select(hotbarSlot)` | Редактирование ссылок и выбора без передачи владения. |
| `EquipInventorySlot(inventorySlot)` | Общий маршрут прежней кнопки экипировки. |
| `TryUsePrimary()`, `TryUseSecondary()`, `TryDropActive()` | Проверенные команды; не вызывать из каждого предмета свой опрос клавиатуры. |
| `CaptureAssignments()`, `RestoreAssignments(ids, selected)` | Снимок ссылок / восстановление после замены всех хранилищ общим загрузчиком. |
| `ValidateSavedAssignments(ids, selected, configuredSlotCount, ownedIds, out error)` | Проверяет размер/индекс/повторяющиеся ID. Отсутствующие в рюкзаке ID при Restore очищаются. |

`ItemStorage.Changed` перепроверяет назначения. Полный перенос, продажа, выброс или расход очищают исчезнувший ID. Частичный расход/выброс сохраняет ID оставшейся стопки. При split/merge сохраняются существующие правила ItemStorage: хотбар не переходит сам на другую стопку того же типа, даже если это тот же предмет по названию. Будущая торговля вызывает прежний ItemStorage API; специальный второй учёт хотбара ей не требуется.

В `PlayerWeapons` остаются прицеливание, перезарядка, выстрел/попадание и таймеры. Если есть активный хотбар, только он маршрутизирует Attack; прежний цикл оружия отключён. Публичный `Equip` делегирует хотбару, внутренний `EquipFromHotbar` не создаёт рекурсивную экипировку. Урон учитывает `Progression.PlayerStatModifiers.Evaluate`, данные WeaponDefinition не изменяются. Не дублировать урон в хотбаре.

Хотбар выполняется перед Update оружия: `TryAttack` читает актуальное действие Aim в момент выстрела, поэтому одновременные ПКМ/ЛКМ используют прицельный разброс сразу. При одновременном R/ЛКМ допустимая перезарядка имеет прежний приоритет; если магазин полный/нет патронов, обычная атака остаётся доступной. `WorldItemDropService` принимает Transform/позицию ног/ItemStorage, поэтому будущий NPC может повторно использовать ту же операцию без FirstPersonController; проверка жизни остаётся у вызывающего адаптера.

`IPlayerItemUseHandler` — расширение для будущих инструментов/способностей: компонент игрока объявляет `CanHandle(ItemStack)` и `TryUsePrimary/Secondary(PlayerHotbar, ItemStack)`. Хотбар сначала использует существующие Weapon/Consumable адаптеры, затем первый активный обработчик обычной вещи. Обработчик проверяет собственные условия и меняет предмет только через ItemStorage; успех возвращает один раз после фиксации. Скрипт не должен читать Mouse/Keyboard самостоятельно. Прототип еды/воды применяется мгновенно, полные анимации рук и длительный use пока не добавлены; будущая длительная операция должна явно иметь отмену до commit.

Меню, смерть, потеря фокуса, пауза времени, спринт и паркур блокируют применение. Выбор другой вещи отменяет незавершённое действие оружия. После возврата управления/смены вещи ЛКМ нужно отпустить перед новым использованием, поэтому закрытие меню щелчком не превращается в выстрел или употребление. `PlayerProgressionMenu` использует общий `motor.GameplayInputEnabled`, без отдельного разрешения атак.

В `Assets/InputSystem_Actions.inputactions` добавлены `Slot1`…`Slot5`, `HotbarScroll` (Axis), `Drop`. Существующие GUID остальных действий и старых цифровых bindings сохранены: Keyboard1/2 перенаправлены на Slot1/Slot2, у Previous/Next остаётся геймпад. `Move/Look/Interact/Aim/Reload` не удалены. Хотбар получает действия только из runtime-копии `FirstPersonController` и обновляет ссылки после её замены. Не добавлять параллельную независимую карту для игрового Attack.

`scrollStep` по умолчанию 1 для нормализованного scroll/y Input System. Дробные движения накапливаются, большое значение проходит несколько шагов; весь оборот возвращает в тот же слот. Если проект намеренно переключён на платформенные сырые scroll deltas, нужно согласовать `scrollStep` с этим режимом. В автоматических тестах `QueueStateEvent` передаёт уже нужное логическое значение (1), а не имитирует нативное преобразование 120 → 1.

Сохранение назначений входит в общий файл игрока этапа 12: ID и выбранный индекс восстанавливаются после всех ItemStorage, затем синхронизируется оружие. Загрузка не создаёт вещи. При изменении настроенного размера используются существующие первые слоты, выбор ограничивается текущим размером. Правило миграции старого формата, ограничения Wallet и проверка файла остаются ответственностью общего `PlayerSaveSystem`.

## Проверка в личном полигоне

1. E взять топор, пистолет/патроны, еду и воду; Tab назначить первые четыре слота, пятый оставить пустым. Назначить ту же вещь в другое место: старое назначение очищается, количество не меняется. Проверить замену и ×.
2. Пройти 1–5, колесо в обе стороны, D-pad; пустой слот убирает оружие. В Tab и дереве развития колесо/ЛКМ не переключают/не применяют вещь. Закрыть меню с удерживаемой ЛКМ: действия нет до отпускания.
3. Пистолет: R, один выстрел на нажатие, Aim, прежние преграды/фракции/боезапас. Топор: один отложенный удар, отмена сменой/меню/паркуром. Выбор еды/воды запрещает стрельбу старым оружием.
4. ЛКМ по еде/воде уменьшает стопку на 1 только при полезном эффекте; удержание не расходует всю стопку. ПКМ ничего не съедает. Полные показатели и смерть не тратят вещь.
5. Q частичной стопки оставляет её назначение; Q индивидуального оружия переносит тот же ID/магазин/прочность в мир и очищает слот. Стена/занятое место сохраняют вещи. Сравнить с «Выбросить 1 / всё» в рюкзаке.
6. Полный и частичный перенос в ящик, merge/split, продажа через ItemStorage: число вещей сохраняется, отсутствующие ID очищаются. Назначение не переезжает на случайную стопку.
7. F5 → изменить предметы/выбор → F9; повторить после перезапуска. ID/боезапас/прочность/назначения соответствуют одному снимку, дубликатов нет. Проверить старый файл и изменение slotCount.
8. Повторить Play с выключенными Scene/Domain Reload, отключение/включение компонента и замену runtime-карты: нет второго ввода/двойного выстрела/старых таймеров. Проверить HUD на широком и узком Game View.

Проверено в отдельной копии проекта Unity 6000.6.3f1: Play smoke `HotbarEdgeSmokeEntry.Run` завершился `HOTBAR_EDGE_SMOKE_OK` (29 проверок). Использовались реальные Input System события 1/2/5, scroll/y, ЛКМ/ПКМ, Q; проверены пустой слот, расход, UI-блокировка, отпускание ЛКМ после меню, приоритет R, одновременное прицеливание/выстрел, переносы и отказ выброса, дубли/пропавшие ID, отключение/включение и замена runtime-карты. Временный тестовый MonoBehaviour находится только в копии и не входит в игровые ассеты. Отдельно root проверил два последовательных Play без Scene/Domain Reload и просмотрел GameView1280×800; подробности — CharacterProgression.md.

Дополнение CM-05 проверено в изолированном Play (CM05_SMOKE_OK): настоящий E-подбор, merge с сохранением принимающего ID, overflow в новую стопку, полный хотбар, отказ без места, оригинальные ID/магазин оружия, запрет ручных/авто назначений патронов, изменение флага и очистка старой ссылки без удаления вещи, отсутствие автозаполнения из обычного Changed/выдачи. Межпроцессный ручной save/Continue сохраняет назначения и экземпляры совместно с миром (SaveSlots.md).
