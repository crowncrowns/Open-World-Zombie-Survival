# Unity game: рабочие ориентиры для разработчиков и ИИ

- Unity 6000.6.3f1, Input System, AI Navigation, URP. Сначала читать Docs/CharacterDevelopment.md и документы конкретной механики.
- Личный полигон: Assets/CharacterTesting/CharacterTest.unity. Игрок: Assets/CharacterTesting/Prefabs/CharacterTestPlayer.prefab. Общий зомби: Assets/Characters/Enemies/ZombieMaleActor.prefab. Исходную Assets/Scenes/SampleScene.unity второго разработчика без необходимости не менять.
- Общие контракты: Docs/ActorIntegration.md. Один ActorIdentity и один IDamageable на корне актёра; новые актёры используют Health. CombatTarget проверяет отношения и жизнь цели. Не добавлять второй IDamageable в другой файл/namespace для обхода ошибок.
- Модель заменяется отдельно через PlayerVisual/PlayerModelDefinition; физика, ввод, инвентарь и AI не должны зависеть от Asuna или имени ZombieMale. Не править vendor-папки для механик проекта.
- Ползание NPC, два NavMesh и настройки фракций: Docs/CrawlPursuitAndSettings.md. Инвентарь и сохранность предметов: Docs/Inventory.md. Шум GameplayNoise не сообщает скрытый Transform. Не ослаблять проверку прямой видимости ради преследования под крышей.
- Все новые сериализованные настройки игрока/монстров снабжать содержательным Tooltip на русском с единицами измерения. Общие настройки собраны в Tools/Zombie Survival/Настройки персонажа и зомби. Расширять вкладки, не заводить дублирующий источник значений.
- Этап 9 выполнен до этапа 8; этап 10 (бой/экипировка) реализован прототипом; далее этап 11. Этап 12 зарезервирован под прокачку. Не включать незаказанные крафт, сохранения и прокачку в контроллер движения.
- При мердже сохранять .meta/GUID, связи префабов и Input Actions: Move, Look, Sprint, Crouch, Jump, Roll, Prone, Interact, SlowWalk. Interact — одно действие на нажатие. Контроллер использует runtime-копию InputActionAsset; UI-команды могут работать при отключённой карте движения.
- Проверки: Tools/Zombie Survival/Validate Actors in Open Scene; ручные сценарии из Docs. Изменения физики/AI проверять в Play, перенос предметов — на заполненных слотах и на сохранение общего количества. Не считать компиляцию доказательством навигации под крышей.
- Не запускать второй Unity на уже открытом checkout и не завершать редактор пользователя. Для batch-проверок использовать отдельную копию с той же версией Unity; временные тестовые MonoBehaviour не переносить в продукт. При переносе авторских ассетов из копии сохранять их .meta и ProjectSettings/NavMeshAreas.asset.
- Не перезаписывать изменения другого разработчика и не создавать коммит/пуш без запроса. Комментарии объясняют контракт/причину, документация — точки расширения и сценарии проверки.

- Звуки: Docs/ActorAudio.md, общий ActorAudioEmitter + заменяемые ActorAudioProfile, адаптеры PlayerMovementAudio/NavMeshActorAudio. AudioSource не подменяет GameplayNoise. Оригиналы Footsteps - Essentials/FreeWeaponSFX/Tybug Studios не менять; обработанные шаги и шорохи лежат в Assets/Audio/Generated. Голоса берутся из Tybug Studios/Zombie Voice Pack - Free. Звуковые параметры собраны во вкладке Звук.
- Взаимодействие: камера назначается явно в префабе и восстанавливается после обновления. PlayerInteractor не должен держать старую InputAction после замены runtime-карты. Проверять подсказку и реальное E после потери ссылки/повторного Play; не ограничиваться прямым вызовом Interact.
- Ползание NPC определяется реальной непроходимостью стоячего объёма при проходимом низком объёме, а не самой позой игрока. До входа NPC идёт стоя. Снимок замеченного входа ограничен по времени и не должен стать отслеживанием скрытого Transform.

- Оружие: Docs/Weapons.md. WeaponDefinition — тип, ItemStack.LoadedRounds — конкретный магазин. Состояние переносить через TransferTo/TryAddStack/WorldItem.Initialize(ItemStack), не воссоздавать TryAddAll. WeaponHitQuery использует общие фракции/Health; PlayerWeapons не ставить на NPC. R — reload живому / respawn мёртвому. Новые действия Aim/Reload сохранять при мердже.

## Постоянное правило документации
После каждого изменения проекта обновляйте инструкции для второго разработчика и его ИИ: AGENTS.md и соответствующий документ Docs. Указывайте контракты, затронутые пути, ограничения и ручную проверку. World-space UI: см. Docs/WorldSpacePresentation.md.

- Пользователь разрешил при реализации механик создавать необходимые props, NPC и работающие тестовые кнопки/консоли в CharacterTest, а при нехватке места расширять полигон с сохранением существующих станций. Перед изготовлением заменителей искать подходящие ресурсы в библиотеке ассетов пользователя: персонажи для торговцев и готовый префаб верстака могут уже быть доступны. Проверять реальные ассеты, не предполагать наличие по названию пакета; авторские обёртки хранить вне vendor-папок. Добавляемые объекты должны демонстрировать реализованную механику. Это разрешение не означает автоматически начинать ещё не заказанные этапы.

- План торговцев, торговли и ремонта: Docs/TradingAndWorkbenchPlan.md. Т1 завершён спецификацией Docs/TradingAndRepairRules.md; Т2 реализован: категории и состояние экземпляров; Т3–Т13 ещё не реализованы. Подтверждено пользователем: рубли отдельным балансом без веса/слота, ремонт ТОЛЬКО материалами (Wallet не затрагивается). Сначала обобщить состояние ItemStack и атомарные операции ItemStorage, сохранять прочность/ID/магазин. Торговец меняет специализацию данными без сброса остатков; верстак открывается через E, улучшения недоступны. Сохранения согласовать с этапом 11; нумерацию этапов 11–12 не менять. Следующие этапы начинать по заданиям пользователя.


- Индикатор HP зомби: небольшое полое красное кольцо без цифр (прозрачный центр), белая радиальная дуга показывает потерю здоровья от 12 часов по часовой стрелке. Историческое имя HollowHealthRing сохранено ради GUID; актуальный контракт и настройки — Docs/WorldSpacePresentation.md.

- Т2 реализует категории/прочность в существующих ItemDefinition/ItemStack/ItemStorage, без экономики/боевого износа/ремонта. GetSlot — живая read-only ссылка; Copy — non-transferable snapshot. Переносить оригинал через TransferTo/TryExtract/TryAddStack/WorldItem.Initialize. Подробности и legacy migration — Docs/Inventory.md; тестовая зона — Docs/ItemStateTests.md. Настройки типа доступны во вкладке Инвентарь существующего окна актёра.

- Т3: Wallet — единый контракт целых рублей (long), отдельно от ItemStorage. TraderBudget только адаптирует finite/infinite, не хранит вторую валюту. Infinite источник/приёмник сохраняет конечный резерв неизменным. Ремонт Wallet не затрагивает; API и тестовые консоли — Docs/WalletAndBudgets.md.
