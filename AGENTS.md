## Постоянное правило документации
После каждого изменения проекта обновляйте инструкции для второго разработчика и его ИИ: AGENTS.md и соответствующий документ Docs. Указывайте контракты, затронутые пути, ограничения и ручную проверку. World-space UI: см. Docs/WorldSpacePresentation.md.

CM-01–CM-03 реализованы вместе с этапом 12: хотбар 5 слотов по умолчанию, 1–5/колесо/D-pad, Q выброс одной единицы, ЛКМ/ПКМ использование. Назначения по InstanceId собственного ItemStorage без копий; 1/2 больше не перебирают оружие. CM-04 выполнен прототипом одной сцены; CM-05 реализован таймером/слотами/меню; CM-06–CM-08 не объявлять готовыми.
- CM-05: Docs/SaveSlots.md. PlayerSaveSlots поверх единого PlayerSaveSystem: 300 с активной игры, 3 авто + 3 ручных слота, F6 меню (также мёртвому), F5/F9 отдельный quick. - CM-04: WorldSaveRegistry один на сцену; WorldSaveObject + SaveIdentity на корне, адаптеры Actor/Identity/Door/Toggle/Wallet/Rigidbody по механике. Сценовый список полный, ID не меняется при каждом Play. Сценовое удаление — RemoveFromWorld (tombstone, сохраняются внешние ссылки), runtime-создание — registry.Spawn(WorldPrefabDefinition,...). Runtime Destroy распознаётся после конца кадра; для Save в том же кадре использовать RemoveFromWorld. Вложенные WorldSaveObject и двойное владение WorldItem запрещены; дочерние ItemStorage имеют отдельные ID.
- CM-04 формат: неизвестная область/тип/revision/Key/Version и занятые будущие позы отказывают ДО изменения мира. Health.WorldStateRestored/Toggle.StateRestored — только идемпотентное представление, не повторение Died/Revived/Interacted и не выдача лута/XP. Подробности и новый WorldSaveAdapter — Docs/WorldSaving.md.
